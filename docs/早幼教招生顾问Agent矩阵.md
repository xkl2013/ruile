## 0. 一句话结论

**给招生顾问配的不是 10 个功能按钮，而是一支 10 人的 AI 小队。**

按 D13 的口径，这 10 个 Agent 全部以**岗位/角色名**命名，覆盖早幼教招生从「获客 → 邀约 → 到访 → 体验 → 转化 → 入园适应 → 转介绍 → 复盘」的完整链路，每个岗位职责互不重叠，一线招生老师用一句话就能找到"这件事该找谁"。

在 PRD 已确认的岗位清单里只列了「招生顾问」一岗。本文把它拆成 **1 个主岗（对外的"招生顾问"本体）+ 9 个协同岗**，构成一个可直接绑到「招生增长」服务模板上的默认专家组合。

## 1. 设计口径（先读这一段）

### 1.1 命名口径：为什么不用"XX助手"

`服务模块重构PRD.md` §3.5.5 是硬约束，三条不可违反：

| 规则 | 合规示例 | 违规示例 |
| --- | --- | --- |
| **用岗位名** | 招生顾问、邀约专员、入园适应顾问 | 话术生成助手、异议处理专家 |
| **不用能力名** | — | "跟进提醒专家""线索清洗助手"（实现视角，用户不知道找谁） |
| **不用技术名** | — | `lead_intake`、`builtin:lead-clean`（不得出现在界面） |

> 因此本文刻意**没有**采用"线索清洗 Agent""话术生成 Agent"这类叫法。能力视角的名称只在内部 `spec.agents[].skills` 字段里出现，界面上一律显示岗位名。

### 1.2 一个必须说清的设计分叉

"招生顾问必备的 10 个 Agent"存在两种解读，产物形态不同，本稿采用 **(B)**：

| | (A) 10 个独立专家包 | **(B) 1 个专家包 + 10 个岗位专家（本稿采用）** |
| --- | --- | --- |
| 形态 | 10 个 `ExpertPackage`，各自独立导入发布 | 1 个 `ExpertPackage: enrollment-growth`，内含 10 个 `spec.agents[]` |
| 用户感知 | 专家目录里 10 个平铺条目 | 建服务时选「招生增长」模板，默认带出一支小队；也可单个增删 |
| 符合 D13 | ✗ 岗位与能力混层 | ✓ 每行都是一个岗位 |
| 运营成本 | 10 次导入/评测/发布/回退 | 1 次，版本统一升降 |
| 复用 | 跨行业难复用 | 幼儿园/托育/早教可各出一套模板，共享同一批岗位定义 |

**推荐 (B)**，理由：D13 把"服务"定义为虚拟小团队，专家是团队成员；分包会让「招生顾问」这个岗位在专家目录里被切碎，用户回到"面对空目录不知从何选起"的状态（PRD §3.5.5 原文担忧）。

### 1.3 单个 Agent 的定义模板

每一个 Agent 在本稿中按同一组字段描述，与 `外部Agent包兼容与管理员发布路线.md` §3.1 的包结构一一对应：

```yaml
- id: enrollment-advisor          # 内部技术 id，不出现在界面
  display_name: 招生顾问           # 界面显示 = 岗位名（D13）
  stage: 全链路                     # 覆盖的招生环节
  definition: agents/enrollment-advisor.md
  output_contract: agent_result_v1 # 卡片(标题/摘要/下一步动作) + 报告 + 产物
  skills: [...]                    # 内部能力名，仅开发可见
  capabilities:
    required: [knowledge.read]
    optional: [web.search, artifact.publish]
```

**输出契约（PRD 决策 4）**：服务卡片对用户**只暴露三个业务字段** —— `标题` / `摘要` / `下一步动作`；证据、分析、风险、建议全部下沉到详细报告或产物。

## 2. 招生全链路：10 个 Agent 的位置

```
① 获客 ──▶ ② 线索 ──▶ ③ 触达 ──▶ ④ 到访 ──▶ ⑤ 体验 ──▶ ⑥ 转化 ──▶ ⑦ 适应 ──▶ ⑧ 增长 ──▶ ⑨ 复盘
   │           │           │           │           │           │           │           │
 渠道专员    线索管家    邀约专员    到访接待    体验课设计   价格方案   入园适应顾问  老带新专员  招生复盘
                        (微信+电话)   家长问答 ────┘                                    ↑
                                                                    招生顾问（主岗，横贯全链路）
```

| # | Agent（岗位名） | 覆盖环节 | 一句话职责 | 优先级 |
| --- | --- | --- | --- | --- |
| 1 | **招生顾问** | 全链路 | 主岗入口：承接线索跟进、家长沟通、到访邀约与转化，是模板的默认专家 | **P0** |
| 2 | **线索管家** | 线索 | 线索去重分层、来源打标、跟进节奏（SLA）与超时清单 | **P0** |
| 3 | **渠道专员** | 获客 | 渠道效果对比、地推点位与活动性价比、物料话术 | P1 |
| 4 | **邀约专员** | 触达 | 电话/微信邀约话术、时间协调、爽约唤回 | **P0** |
| 5 | **家长问答** | 到访·转化 | 高频顾虑应答：安全、师资、饮食、卫生、理念、分离焦虑 | **P0** |
| 6 | **到访接待** | 到访 | 园所参观动线讲解、家长关注点应答、到访记录 | P1 |
| 7 | **体验课设计** | 体验 | 亲子体验课/开放日流程、观察记录表、体验后回访 | P1 |
| 8 | **价格方案** | 转化 | 报价口径、优惠组合、价格异议处理、退费规则解释 | **P0** |
| 9 | **入园适应顾问** | 适应 | 适应期家长安抚、分离焦虑引导、每日反馈模板 | P1 |
| 10 | **老带新专员** | 增长 | 转介绍激励方案、口碑素材、家长群运营节奏 | P2 |
| — | **招生复盘** | 复盘 | 转化漏斗、周/月报、渠道与话术归因 | P1 |

> 表内共 11 行 —— 见 §6 Q1：**"招生复盘"是并入主岗「招生顾问」的管理视角，还是单列第 10 岗**，需业务侧拍板。本稿默认并入主岗，故表头称"10 个"（1 主岗 + 9 协同岗）。

## 3. 逐项定义

### 3.1 ① 招生顾问（主岗 · P0）

| 项 | 内容 |
| --- | --- |
| **定位** | 模板的入口专家。家长一句话丢进来，它能判断该走哪条链路，并给出下一步动作 |
| **触发场景** | "这个家长说要考虑一下""明天有个家长来参观，帮我把要说的话理一下" |
| **输入** | 线索信息（宝宝年龄、意向班型、来源渠道）+ 记忆/历史沟通记录 + 园所知识库 |
| **输出·卡片** | 标题：`XX 家长（2岁半 · 意向托班）跟进建议`<br>摘要：3 句内说清当前意向档位 + 卡点<br>下一步动作：1 条可今天执行的动词短语 |
| **输出·报告** | 客户画像、沟通时间线、卡点归因、3 步跟进计划、参考话术 |
| **必备 Skill** | `knowledge_search`、`grep_chunks`、`get_document_info` |
| **知识库** | 园所介绍、班型与学位、收费政策、师资简介、一日流程 |
| **复用** | 现成 `builtin-sales-director`（销售总监）+ `education-sales` preset 已具备雏形，改造为岗位化命名的 P0 版本 |

### 3.2 ② 线索管家（P0）

| 项 | 内容 |
| --- | --- |
| **定位** | 让每条线索"有人管、有节奏、不超时" |
| **触发场景** | "把这周的线索整理一下""哪些家长该跟进了""这条线索和之前那个是同一个家长吗" |
| **输入** | 线索表/表单导出、微信沟通记录截图转写、渠道标记 |
| **输出·卡片** | 标题：`本周待跟进线索 12 条（含 3 条超时）`<br>摘要：按意向档位（A/B/C）分布 + 超时条数<br>下一步动作：`先处理 3 条超时线索，给出话术` |
| **输出·报告** | 线索清单（去重后）、分层依据、来源分布、跟进节奏建议表 |
| **必备 Skill** | `data_schema`、`data_analysis`、`knowledge_search` |
| **知识库** | 招生话术库、跟进 SOP、无 |
| **能力** | `required: knowledge.read` / `optional: artifact.publish`（导出表格） |
| **复用** | 复用 `data-analysis` preset（SQL + 统计），叠加招生领域提示词 |

### 3.3 ③ 渠道专员（P1）

| 项 | 内容 |
| --- | --- |
| **定位** | 算清楚"钱花在哪里最划算" |
| **触发场景** | "这个月地推效果怎么样""小红书投放值不值得继续""下周六社区活动要不要参加" |
| **输入** | 各渠道线索量与转化数据、活动成本、竞品动态 |
| **输出·卡片** | 标题：`9 月渠道复盘：转介绍 ROI 最高（1:6.2）`<br>摘要：三渠道对比 + 一句话建议<br>下一步动作：`把地推预算的 30% 转到老带新激励` |
| **输出·报告** | 渠道 ROI 对比表、单客获取成本、活动性价比排序、下月投放建议 |
| **必备 Skill** | `data_analysis`、`knowledge_search`、`web_search`（查本地竞品活动） |
| **能力** | `optional: web.search` |

### 3.4 ④ 邀约专员（P0）

| 项 | 内容 |
| --- | --- |
| **定位** | 把"线上聊得热"变成"真的走进园所" |
| **触发场景** | "帮我写一段微信邀约""打电话约到访，家长说没时间怎么办""上周约了没来的怎么唤回" |
| **输入** | 家长画像、可到访时段、园所近期开放时段、历史爽约记录 |
| **输出·卡片** | 标题：`李女士（意向小班）到访邀约话术`<br>摘要：首句抓手 + 价值点 + 二选一时间法<br>下一步动作：`今天 19:00 前微信发出，附 3 张实拍` |
| **输出·报告** | 微信版（≤80 字）+ 电话版（含开场/价值/异议/收口）+ 爽约唤回版三套话术 |
| **必备 Skill** | `knowledge_search`、`grep_chunks` |
| **知识库** | 开放日安排、园所实拍素材说明、到访礼政策 |
| **合规** | 不得承诺"一定录取""包进某班"；不夸大师生比等硬指标 |

### 3.5 ⑤ 家长问答（P0）

| 项 | 内容 |
| --- | --- |
| **定位** | 家长最纠结的那几个问题，有标准、有依据、不踩雷 |
| **触发场景** | "家长问监控能不能看""问为什么这么贵""问老师会不会总换""问我们家宝宝过敏怎么办" |
| **早幼教六大高频顾虑** | ① 安全（监控/接送/消防/门禁）② 师资（资质/师生比/稳定性）③ 饮食（食谱/过敏/厨房）④ 卫生（晨检/消毒）⑤ 教育理念（玩中学/课程体系）⑥ 分离焦虑 |
| **输出·卡片** | 标题：`家长问：三餐是自己做的吗`<br>摘要：结论 + 依据出处<br>下一步动作：`把食谱与厨房照片一并发给家长` |
| **输出·报告** | 标准答法 + **依据来源**（政策条款/园所制度文件/资质证书）+ 不宜说的话术黑名单 |
| **必备 Skill** | `knowledge_search`、`grep_chunks`、`list_knowledge_chunks`、`get_document_info` |
| **知识库** | 卫生保健制度、应急预案、师资资质、食谱、课程体系说明 |
| **复用** | 直接复用 `rag-qa` preset；关键在知识库要喂足制度类文档 |
| **合规（重要）** | 涉及安全的回答**必须带出处**，不得编造证照；无依据时输出"需向园所确认"而非猜测 |

### 3.6 ⑥ 到访接待（P1）

| 项 | 内容 |
| --- | --- |
| **定位** | 家长走进园所的那 30 分钟，讲什么、按什么顺序讲 |
| **触发场景** | "明天有家长参观，帮我排一下动线""家长主要想看什么" |
| **输出·卡片** | 标题：`周六 10:00 到访接待方案（2 岁半 · 意向托班）`<br>摘要：动线 5 站 + 3 个必看亮点<br>下一步动作：`提前把宝宝的班级作品准备一份` |
| **输出·报告** | 参观动线（门口→教室→活动区→厨房→卫生间）、每站讲解词、家长提问预判、到访记录表 |
| **必备 Skill** | `knowledge_search` |

### 3.7 ⑦ 体验课设计（P1）

| 项 | 内容 |
| --- | --- |
| **定位** | 亲子体验课 / 开放日的流程与观察记录 |
| **触发场景** | "设计一节 40 分钟的亲子体验课""体验课完了怎么写反馈给家长" |
| **输出·卡片** | 标题：`亲子体验课《小手的旅行》40 分钟流程`<br>摘要：暖场 5' / 主活动 20' / 家长观察 10' / 收口 5'<br>下一步动作：`课后 24 小时内发出宝宝观察反馈` |
| **输出·报告** | 环节脚本、材料清单、安全提示、教师观察记录表模板、体验后回访话术 |
| **知识库** | 课程体系、各年龄段发展目标（3-6 岁指南）、园所特色课程 |
| **合规** | 活动设计须符合幼儿年龄特点，避免超龄/危险器材 |

### 3.8 ⑧ 价格方案（P0）

| 项 | 内容 |
| --- | --- |
| **定位** | 谈钱不尴尬：报得出去，也解释得清楚 |
| **触发场景** | "家长说隔壁园便宜 800""怎么把优惠说得不像打折""能不能分期" |
| **输出·卡片** | 标题：`家长嫌贵（对比隔壁园低 800）应对方案`<br>摘要：先接情绪 → 拆价值 → 给方案<br>下一步动作：`用"日均成本"重述价格` |
| **输出·报告** | 报价口径表、优惠组合方案（早鸟/双胞胎/转介绍）、价值拆解话术、**退费规则标准答法** |
| **必备 Skill** | `knowledge_search`、`grep_chunks` |
| **知识库** | 收费公示、优惠制度、退费办法 |
| **合规（红线）** | **不得作出虚假优惠、不得隐瞒退费条款**；优惠方案必须能在制度文件中找到依据（《民促法》及地方收费管理要求下的合规表述） |

### 3.9 ⑨ 入园适应顾问（P1 · 早幼教特有）

| 项 | 内容 |
| --- | --- |
| **定位** | 早幼教独有的"售后"环节：成交后第一个月不掉链子 |
| **触发场景** | "家长说宝宝哭了三天不想去了""怎么跟家长解释分离焦虑""每天反馈怎么写" |
| **输出·卡片** | 标题：`分离焦虑期家长沟通方案（入园第 3 天）`<br>摘要：先安抚家长情绪 → 给具体进展 → 明确明天动作<br>下一步动作：`今天 17:00 前发一段 15 秒视频` |
| **输出·报告** | 适应期 1-4 周沟通节奏表、每日反馈模板（吃/睡/情绪/互动）、焦虑分级应对、家长送园话术 |
| **知识库** | 一日流程、保育制度、儿童发展常识 |
| **价值** | **直接决定续报与转介绍**——早幼教的口碑基本产生在这一个月 |

### 3.10 ⑩ 老带新专员（P2）

| 项 | 内容 |
| --- | --- |
| **定位** | 把满意的家长变成招生的第二条腿 |
| **触发场景** | "设计一个转介绍激励""家长群怎么运营""想拍一组家长口碑视频" |
| **输出·卡片** | 标题：`10 月转介绍激励方案（老带新各得 500 元课时）`<br>摘要：激励设计 + 触发时机 + 素材清单<br>下一步动作：`这周五在家长群发起"带朋友来玩"活动` |
| **输出·报告** | 激励规则、触达节点（适应期满/学期末/毕业季）、社群周运营脚本、口碑素材脚本 |
| **合规** | 转介绍激励不得承诺以现金形式变相返现（视地方规定），优先以课时/服务形式 |

### 3.11 ⑪ 招生复盘（并入主岗 · P1）

| 项 | 内容 |
| --- | --- |
| **定位** | 每周给园所一张"招生体检表" |
| **触发场景** | "这周招生情况怎么样""为什么邀约来了但没成交" |
| **输出·卡片** | 标题：`第 40 周招生复盘：到访 18 → 成交 4（22%）`<br>摘要：漏斗各环节转化率 + 最大流失点<br>下一步动作：`把"体验课到场率"从 61% 提到 75%` |
| **输出·报告** | 转化漏斗表、环节归因、TOP3 卡点与改法、下周三件事 |
| **复用** | 复用 `data-analysis` preset |

## 4. 与现有资产的对照（复用 vs 新建）

| Agent | 现有可复用资产 | 动作 |
| --- | --- | --- |
| 招生顾问 | `builtin-sales-director`（销售总监，`education_sales_director` 提示词）+ `education-sales` preset | **改造**：改岗位化命名 + 收紧输出契约 |
| 家长问答 | `builtin-quick-answer` + `rag-qa` preset | **直接复用**，只换知识库与提示词 |
| 线索管家 / 招生复盘 | `data-analysis` preset（`data_schema` + `data_analysis`） | **复用 preset**，叠加招生字段口径 |
| 邀约专员 / 价格方案 / 到访接待 | 无 | **新建**（提示词为主，不新增工具） |
| 渠道专员 | 无（需 `web_search` 可选能力） | **新建** |
| 体验课设计 / 入园适应顾问 / 老带新专员 | 无 | **新建**，但都只依赖 `knowledge_search`，开发成本低 |

**结论**：10 个 Agent 中 **4 个可复用现有基座**，**6 个新建但全部不需要新工具**——只写提示词 + 绑知识库即可。这意味着本矩阵的交付风险主要在**知识库内容质量**，不在工程实现。

### 5.2 分三批

| 批次 | 内容 | 判断依据 |
| --- | --- | --- |
| **第一批** | ① 招生顾问、② 线索管家、④ 邀约专员、⑤ 家长问答、⑧ 价格方案 | 这 5 个覆盖"线索→到访→成交"主干，缺一环链路就断 |
| **第二批** | ⑥ 到访接待、⑦ 体验课设计、⑨ 入园适应顾问 | 体验与留存环节，决定续报率 |
| **第三批** | ③ 渠道专员、⑩ 老带新专员、（⑪ 招生复盘） | 增长与复盘，依赖前两批产生的数据 |

### 5.3 与「招生增长」服务模板的绑定

在 `service_templates.config.experts` 里预置默认组合（PRD §5.2.9）：

```yaml
# 幼儿园 · 招生增长
experts: [enrollment-advisor, lead-steward, invitation-specialist, parent-faq, pricing-advisor]
```

托育中心、早教中心的模板可在此基础上增减（例如托育更重「入园适应顾问」），**共享同一批岗位定义**——这正是分包方案做不到的。
