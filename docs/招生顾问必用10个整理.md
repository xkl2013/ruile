## 0. 为什么重做：上一版的 4 条结论已作废

平台在 2026-10-07 上线了**批量查询 + 自动拆批 + 批次合并**。这直接改变了模板该怎么设计：

| 上一版（v1.0）的说法 | 现在的实际 | 对模板的影响 |
|---|---|---|
| 触发只有两种：**人工勾选多条** / 定时取**最近一批** | 触发改为「**按要求整理**」：用自然语言描述**时间范围 + 记忆类型 + 关键词**，先预览命中数再确认；**周期任务也解析配置指令**（`organize_workbench.go:966-991`） | 模板的**默认指令**同时决定"取哪些记忆"，要写清时间与类型 |
| 前端**没有多选**，聚合型只能走定时 | 不需要多选了：**按指令查询**即可圈定范围；超预算**自动拆批**（14000 字符/批）再**合并** | ⑥⑧ 这类聚合模板**不再受限**，可按需触发 |
| 聚合靠"取最近一批"，**覆盖不全也无感知** | 父任务记录 `selected/ready/processed/failed/overlap/batch_count`，并写入 `metadata.coverage`，前端展示覆盖率 | 覆盖面**可见**了，可放心设计聚合模板 |
| 多批结果**无法合并**（建议"回写法"绕行） | 已有正式合并阶段（`organize_batch.go:129-151`），提示词要求**去重 + 冲突入"待确认" + 保留来源引用**；**明确不做**"中间结果回写成记忆" | **不要**再设计回写法，与研发口径冲突 |

**一句话**：模板设计从"想办法把多条记忆凑进一次调用"，变成"**声明查询范围 + 整理要求**，其余交给平台"。

## 1. 判据（保持不变）

只保留同时满足四条的：

| # | 门槛 | 不满足的例子 |
|---|---|---|
| 1 | 输入是**顾问本来就会录的记忆**（文字/录音/上传） | 渠道投放 ROI —— 需要外部数据 |
| 2 | 输出能由**模型从自然语言记忆直接产出** | 招生漏斗复盘 —— 没有"阶段"字段 |
| 3 | **不依赖未接线的能力** | 按家长聚合档案 —— 没有 `subject_id` |
| 4 | 要么**省时间**，要么**作用在转化/口碑指标上** | 单纯资料归档 |

**新增第 5 条（本版）**：模板的**查询范围必须能用自然语言表达**——因为范围就是这么指定的。表达不出来的（如"所有价格敏感型家长"），本版一律不设计。

## 3. 十个模板的完整配置

每个模板给出四件可直接落地的东西：**默认指令**（同时是查询范围和整理要求）｜**章节骨架**（含表格，决定"抽取什么"）｜**结构化字段**（`spec.fields`，决定后续能否筛选）｜**触发**。

> **骨架必须手写，不要用 `compile`**：`compile` 的表格列是**按章节关键词硬编码的活动策划列**（只认 `流程/人员/物料/预算`，列为`时间/环节/负责人/风险控制` 等，`organize_template_compiler.go:162-177`），**生成不出招生列**。手写 `markdown_template` + `spec.sections` 才有正确的表格。
> 骨架硬约束（由平台强制）：章节名含「待办/下一步/行动/跟进」自动转 `- [ ]`；输出**必须保留全部章节**，模型漏掉会**自动补回并标「记录中未提供」**；**表格占位符必须展开为完整 Markdown 行**；上限 12000 字符。

## 5. 这 10 个整理现在怎么被"跑起来"

### 5.1 主链路：按要求整理（v2.0 新增能力）

```text
自然语言指令
  → 结构化查询计划（时间范围 / 记忆类型 / 关键词）
  → 查询记忆
  → 预览命中数与预计批次数（确认前可见）
  → 固化输入快照（memory_ids + 记忆版本 + 内容哈希）
  → 按 14000 字符预算自动拆批
  → 逐批整理（Map）
  → 合并批次摘要（Reduce，去重 + 冲突入"待确认" + 保留引用）
  → 产出唯一一份用户可见成果
```

**支持的时间表述**（`organize_selection.go:33-117`）：今日 / 昨日 / 本周 / 上周 / 本月 / 上月 / 单日 / 中文日期区间。
**支持的类型表述**：录音卡 / 录音 / 笔记 / 记录；"只处理已完成"→ `ready_only`。
**单次最多固定 1000 条**记忆，**每批预算 14000 字符**，单条估算最多计 2200 字符。

### 5.2 周期任务：也解析配置指令（口径已变）

`createScheduledOrganizeJob` 会**先解析 `config.Instruction` 得到查询计划**，再按时间范围/类型查记忆（`organize_workbench.go:966-991`）；只有指令里没有任何条件时，才退回"取最近一批"。

> 所以旧口径「自动跑＝只能把最近录的整理一遍」**已作废**。现在配置指令写"整理本周的招生咨询录音"，周期任务就真的只处理本周的。

### 5.3 覆盖率可见（v2.0 新增）

父任务记录 `selected / ready / processed / failed / overlap / batch_count`，并写入成果的 `metadata.coverage`（`organize_workbench.go:820-821`、`organize_batch.go:169-185`）。**"本次覆盖 N/M 条"已经实现**，不用再担心用户把"只覆盖一部分"误读成"AI 漏了"。

### 5.4 成果能进服务、能绑专家

- **进服务**：配置可绑 `TargetServiceID`（`000116_organize_service_assignment.up.sql`），成果自动指派到服务空间，服务专家运行时读得到
- **带岗位视角**：`GET /api/v1/organize/experts` + 模板 `expert_ids` + 任务「参与专家」会进提示词（`organize_workbench.go:910-913`），**但预置模板 `expert_ids` 全是 `[]`** —— 给这 10 个各绑一个「招生顾问」专家，零代码

### 5.5 产出能筛选（读侧已通，写侧未接）

`GET /api/v1/organize/outputs?field.<key>=<value>` **端到端可用**（`handler/organize.go:1050-1065` → `repository/organize.go:399-401` → `applyOrganizeJSONTextFilter:698-708`，等值匹配顶层 key）。

## 6. 唯一待接线点：`spec.fields` → `output.fields`

这是本版**唯一**需要研发配合的地方，其余全靠配置。

| 环节 | 现状 |
|---|---|
| 模板声明 `spec.fields` | ✅ 支持，且**有校验**（强制 `key` + `label`，`organize_admin.go:386-425`） |
| 骨架里写表格 | ✅ 契约强制模型**必须填满 Markdown 行**（`organize_markdown_template.go:100`）→ **今天就能得到"表格形态的结构化结果"** |
| 任务产出写 `output.fields` | ❌ **仍只写 6 个系统字段**（主题/模板/模板版本/涉及时间/待办数/来源数，`organize_workbench.go:803-810`），**不读模板声明的 `fields`** |
| 按字段筛选 | ✅ 读侧已通，**只等写侧** |

**结论**：本版 10 个模板的 `spec.fields` **现在可以先声明**（校验能过、不影响运行），一旦研发把 `spec.fields` 回填到 `output.fields`，`?field.异议类型=价格`、`?field.渠道=点评` 这类筛选**立刻可用**，不需要再改模板。

**建议的落地顺序**：

| 批次 | 做什么 | 成本 |
|---|---|---|
| **第一批（本周）** | 直接用现成的 ①③⑨，拿真实招生记忆跑一遍 | **0** —— 验证产出实际质量，这是最大未知数 |
| **第二批** | 建 ④⑤（每单复盘），高频刚需 | 2 张模板 |
| **第三批** | 建 ②⑥⑦⑧⑩，并给 ①②③⑥⑦⑧⑩ 设周期（daily/weekly/monthly） | 5 张模板 + 配置 |
| **收尾** | 给 10 个模板绑「招生顾问」专家；向研发提 `spec.fields` 回填 | 配置 + 1 条需求 |

## 7. 必须守住的口径

**所有整理的天花板 = 顾问录了多少记忆。**

记忆为空或范围没命中时，任务不会产出虚构内容（查询无结果时**不创建模型任务**）。对外只能这样讲：

- ✅ **「你录进来的，我帮你整理成能用的清单和台账」**
- ✅ **「每天早上自动给你一份跟进清单」**（已实现）
- ✅ **「你可以直接说'整理本月含异议的沟通'，它自己圈范围、分批复、合并成一份」**（v2.0 新增，已实现）
- ❌ **不能**说「AI 自动帮你盯着客户」——服务提醒的自动生成链路在代码里尚未接线
- ❌ **不能**说"按家长自动归档"——记忆表没有 `subject_id`
