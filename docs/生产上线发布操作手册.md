# 生产上线发布操作手册

本文适用于当前标准版 Docker Compose + 阿里云 ACR/ECS 部署方式。目标是让每次上线都具备固定版本、可验证、可回滚的发布记录。

## 0. 发布原则

- 每次发布使用新的不可变镜像 tag，不使用 `latest`。
- 先备份数据库、`.env` 和文件存储，再升级应用。
- 数据库迁移只向前执行，不把 `migrate down` 当作生产回滚方案。
- 本版本的计费先保持 `off` 或 `observe`，不要直接切换 `enforce`。
- 本次删除 WeKnora Cloud 配置入口前，先确认线上没有仍依赖该入口的云模型。

## 1. 本地发布前检查

在项目根目录执行：

```bash
cd /Users/jamgogh/Desktop/agent/ruile
git status --short
git diff --check
```

工作树应当干净。将本次修改提交后再构建：

```bash
git add <本次修改文件>
git commit -m "release: prepare production build"
```

执行只读检查：

```bash
./scripts/release_preflight.sh --tests
```

如果只需要检查构建环境、不跑测试：

```bash
./scripts/release_preflight.sh
```

该脚本不会推送镜像、修改数据库或重启服务。若确实要打包未提交代码，必须显式指定临时 tag：

```bash
./scripts/release_preflight.sh \
  --allow-dirty \
  --tag dirty-$(date +%Y%m%d%H%M)
```

## 2. 生成发布版本

推荐使用当前提交短 SHA 作为镜像 tag：

```bash
TAG="$(git rev-parse --short HEAD)"
echo "$TAG"
```

如果需要人工版本号，使用日期或语义化版本，例如：

```bash
TAG="20260919-001"
```

发布记录至少保存以下信息：

```text
版本 tag:
Git commit:
构建时间:
数据库迁移前版本:
数据库迁移后版本:
发布人:
回滚镜像 tag:
```

## 3. 构建并推送 ACR 镜像

先在项目根目录创建本地 `.acr.env`，不要提交到 Git：

```bash
cat > .acr.env <<'EOF'
ACR_REGISTRY=registry.cn-beijing.aliyuncs.com
ACR_NAMESPACE=rl-knowledge
ACR_USERNAME=<ACR_USERNAME>
ACR_BUILD_PLATFORM=linux/amd64
ACR_BUILDER_PLATFORM=linux/arm64
USE_ACR_BASE_IMAGES=true
EOF
chmod 600 .acr.env
```

`ACR_PASSWORD` 可以不写入文件，脚本会安全地交互读取。构建和推送：

```bash
./scripts/build_and_push_acr.sh --tag "$TAG"
```

脚本会构建并推送以下镜像：

```text
weknora-app
weknora-docreader
weknora-ui
weknora-sandbox
```

Admin 是独立前端镜像，主 ACR 脚本虽然会构建它，但不会推送。若本次包含 Admin 改动，再执行：

```bash
./scripts/deploy/deploy_admin_acr.sh --tag "$TAG"
```

推送后检查：

```bash
docker manifest inspect \
  "registry.cn-beijing.aliyuncs.com/rl-knowledge/weknora-admin:${TAG}"
```

检查镜像是否已推送：

```bash
docker manifest inspect \
  "registry.cn-beijing.aliyuncs.com/rl-knowledge/weknora-app:${TAG}"
```

## 4. 上线前在 ECS 备份

登录 ECS 后执行。以下命令不会删除现有数据：

```bash
cd /opt/WeKnora
mkdir -p backups
cp .env "backups/env-before-${TAG}"

docker exec -t WeKnora-postgres \
  sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' \
  | gzip > "backups/postgres-before-${TAG}-$(date +%Y%m%d%H%M%S).sql.gz"
```

如果使用本地文件存储，再备份 `/data/files` volume：

```bash
DATA_VOLUME="$(docker inspect WeKnora-app --format '{{range .Mounts}}{{if eq .Destination "/data/files"}}{{.Name}}{{end}}{{end}}')"
docker run --rm \
  -v "${DATA_VOLUME}:/data:ro" \
  -v "$PWD/backups:/backup" \
  alpine tar czf "/backup/data-files-before-${TAG}.tgz" -C /data .
```

如果使用 OSS，不要只备份数据库。应确认 OSS 的版本控制、跨区域复制或最近一次对象同步可恢复。

## 5. 检查高风险兼容项

本版本移除了 WeKnora Cloud 的配置页面和旧配置接口，但仍保留部分运行时兼容代码。上线前在 PostgreSQL 执行：

```sql
SELECT COUNT(*)
FROM models
WHERE parameters->>'provider' = 'weknoracloud';
```

结果大于 0 时，不要直接切换生产版本。先确认这些模型是否仍在使用，并准备迁移到新的模型供应商配置。

## 6. ECS 切换镜像并启动

确认 `/opt/WeKnora/.env` 中使用本次 tag。先把 `<new-tag>` 替换为第 3 步推送成功的实际 tag：

```bash
cd /opt/WeKnora
TAG="<new-tag>"

set_env() {
  key="$1"
  value="$2"
  if grep -qE "^${key}=" .env; then
    sed -i "s|^${key}=.*|${key}=${value}|" .env
  else
    printf '%s=%s\n' "$key" "$value" >> .env
  fi
}

set_env WEKNORA_VERSION "$TAG"
set_env WEKNORA_SANDBOX_DOCKER_IMAGE \
  "registry.cn-beijing.aliyuncs.com/rl-knowledge/weknora-sandbox:${TAG}"
set_env AUTO_RECOVER_DIRTY "false"
```

确认 ECS 使用 ACR 镜像覆盖文件：

```bash
cat > docker-compose.acr.yml <<'YAML'
services:
  frontend:
    image: registry.cn-beijing.aliyuncs.com/rl-knowledge/weknora-ui:${WEKNORA_VERSION}
  app:
    image: registry.cn-beijing.aliyuncs.com/rl-knowledge/weknora-app:${WEKNORA_VERSION}
  docreader:
    image: registry.cn-beijing.aliyuncs.com/rl-knowledge/weknora-docreader:${WEKNORA_VERSION}
  sandbox:
    image: registry.cn-beijing.aliyuncs.com/rl-knowledge/weknora-sandbox:${WEKNORA_VERSION}
YAML

COMPOSE=(docker compose -f docker-compose.yml -f docker-compose.acr.yml)
"${COMPOSE[@]}" config --quiet
```

拉取新镜像并启动：

```bash
COMPOSE=(docker compose -f docker-compose.yml -f docker-compose.acr.yml)
"${COMPOSE[@]}" pull
"${COMPOSE[@]}" up -d --no-build
```

说明：

- 当前应用启动时会自动执行待执行迁移。
- `AUTO_RECOVER_DIRTY=false` 用于避免迁移异常时自动强行恢复，便于保留现场排查。
- 不要使用 `docker compose down -v`，它会删除数据库或文件 volume。

检查容器和健康状态：

```bash
COMPOSE=(docker compose -f docker-compose.yml -f docker-compose.acr.yml)
"${COMPOSE[@]}" ps
curl -f http://127.0.0.1:8080/health
"${COMPOSE[@]}" logs --tail=300 app \
  | grep -i -E 'migration|migrat|error|failed|dirty'
```

## 7. 计费开关顺序

迁移完成后，先在 Admin 的系统设置中确认：

```text
billing.enabled = false
billing.enforcement_mode = off
```

完成基础回归后，再按观察模式启用：

```text
billing.enabled = true
billing.enforcement_mode = observe
```

第一阶段不要启用 `enforce`。当前版本的 `observe` 会记录模型实际 Token 和用量账本，但不会扣减成员或企业余额；`enforce` 会执行额度和余额限制，必须在业务验收后单独发布。

重点验证：

1. 登录、个人空间和企业空间切换。
2. 企业成员、归属企业、企业积分和存储用量展示。
3. 模型新增、URL/Key/模型名配置和连通性测试。
4. 普通对话、流式对话、智能体问答。
5. 知识库上传、解析、检索和删除。
6. Admin 的套餐、模型、价格、积分账户、用量账本页面。
7. 智能体调用后，用量账本出现 Token 记录，且没有异常扣减。

## 8. 失败处理与回滚

### 8.1 只回滚应用镜像

如果只是前端或应用启动问题，保留数据库迁移结果，切回上一个镜像 tag：

```bash
set_env WEKNORA_VERSION "<previous-tag>"
set_env WEKNORA_SANDBOX_DOCKER_IMAGE \
  "registry.cn-beijing.aliyuncs.com/rl-knowledge/weknora-sandbox:<previous-tag>"

COMPOSE=(docker compose -f docker-compose.yml -f docker-compose.acr.yml)
"${COMPOSE[@]}" pull
"${COMPOSE[@]}" up -d --no-build
```

### 8.2 数据库迁移异常

不要直接执行：

```bash
make migrate-down
```

先保留日志和数据库备份，确认迁移版本和 dirty 状态：

```bash
COMPOSE=(docker compose -f docker-compose.yml -f docker-compose.acr.yml)
"${COMPOSE[@]}" logs --tail=500 app
"${COMPOSE[@]}" ps
```

只有在确认迁移未产生不可逆数据变化、并完成数据库恢复方案评估后，才允许进行数据库恢复。`000088` 内置模型迁移和 `000089` 提示词清理迁移不提供完整数据回滚，不能依赖 down migration 恢复。

## 9. 发布完成记录

上线后记录：

```text
应用镜像 tag:
Git commit:
数据库迁移版本:
计费模式: off / observe
WeKnora Cloud 模型数量:
健康检查结果:
核心回归结果:
备份文件:
是否保留上一个镜像:
```

生产环境只保留可复现的镜像 tag，不要覆盖已经使用过的 tag。
