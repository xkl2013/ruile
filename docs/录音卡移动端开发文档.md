# 录音卡移动端开发文档

本文档面向 mobile App 与外部录音卡的联调开发，重点覆盖 BLE 连接、设备指令、录音文件同步、断点重传、本地文件落盘和云端同步衔接。

当前 mobile 目录为 Flutter 应用，已有手机麦克风本地录音草稿与 `/api/v1/organize/memories` 创建记忆的基础链路。录音卡接入应作为独立 BLE 设备能力实现，不直接耦合现有手机麦克风录音逻辑。

## 目标范围

### 必须实现

- 扫描录音卡广播，解析广播中的 MAC 与 SN，并展示可连接设备。
- 连接设备后发现指定 Service 与 3 个 Characteristic。
- 支持基础设备指令：获取 SN、同步时间、获取设备信息、电量、内存、录音状态、软件版本。
- 支持远程录音控制：开始录音、暂停/恢复、退出录音、录音时间过短提示。
- 支持文件列表同步：获取本地录音列表，处理分页版本和非分页版本。
- 支持文件数据同步：按 250 字节包接收音频数据、校验、落盘、进度统计、断点续传。
- 支持失败恢复：校验失败时停止当前传输，等待设备返回 `0x09` 后从断点重新拉取。
- 支持删除设备文件，避免 App 同步完成后设备空间持续增长。
- 支持实时录音数据同步，为后续实时转写或分段同步预留。

### 暂不强制实现

- SBC 到 WAV/M4A 的端侧转码播放。
- HID 粘贴模式。
- 修改 SBC 码率、MIC 增益、DRC 增益等有兼容风险的设备参数。
- USB 开关等部分固件可能无效的能力。

## 关键结论

- 命令通道和音频数据通道必须分离：指令写入 `f255202a...`，设备回复从 `f355203a...` 通知，音频包从 `f455204a...` 通知。
- 录音卡上传的是 SBC 文件，参数为 `16000 Hz`、单声道、`s16p`。App 应先原样保存 `.sbc`，再决定是否转码。
- 文件同步必须按字节地址建立 checkpoint。只按包序号恢复不可靠，因为协议返回的是文件起始地址和文件大小。
- 校验失败不能直接继续收包，需要先发停止上传 `0x08`，等设备返回同步文件成功 `0x09` 后再用 `0x07` 从断点地址重传。
- `0x09` 在协议里既表示“同步文件成功”，也作为停止上传成功后的设备返回。实现时应结合当前状态机判断含义。

## BLE 协议基础

### UUID

| 类型 | UUID | 方向 | 用途 |
| --- | --- | --- | --- |
| Service | `f055200a-2323-4545-6767-8989fffefdfc` | - | 录音卡主服务 |
| Characteristic | `f255202a-2323-4545-6767-8989fffefdfc` | App -> 设备 | App 下发指令 |
| Characteristic | `f355203a-2323-4545-6767-8989fffefdfc` | 设备 -> App | 设备回复和主动上报 |
| Characteristic | `f455204a-2323-4545-6767-8989fffefdfc` | 设备 -> App | 设备上传音频数据 |

### 广播数据

广播包包含 `MAC + SN`。部分设备蓝牙地址最后一个字节需要与 `0x55` 做异或后才是实际 MAC：

```text
normalizedLastByte = rawLastByte ^ 0x55
```

开发建议：

- 广播解析同时保留 `rawMac` 和 `normalizedMac`，避免同一固件策略下设备匹配失败。
- 设备唯一键优先使用 `SN`；当 SN 不存在时使用 `normalizedMac`。
- 扫描列表展示 SN、MAC、RSSI、最近发现时间。

### 指令包格式

App 下发指令包：

```text
55 aa <length> <command> [data...]
```

设备回复/上报指令包：

```text
aa 55 <length> <command> [data...]
```

字段说明：

| 字段 | 长度 | 说明 |
| --- | --- | --- |
| 包头 | 2 字节 | App 包头 `0x55 0xaa`；设备包头 `0xaa 0x55` |
| length | 1 字节 | `1 字节 command + N 字节 data` |
| command | 1 字节 | 指令号 |
| data | N 字节 | 无数据时不发送 |

示例：

```text
55 aa 01 01
```

表示 App 获取设备 SN。

```text
aa 55 0f 01 56 6f 52 65 63 41 69 5f 30 30 30 30 32 30
```

表示设备返回 SN，数据为 ASCII 字符串。

## 音频文件包格式

文件传输每包 250 字节，前 10 字节为包信息，后 240 字节为音频数据。

```text
byte 0-1   包头: 0x52 0x58
byte 2-5   文件地址: 4 字节
byte 6     包长: 本包音频数据长度，最大 240
byte 7     头部校验: 前 7 字节累加取低 8 位
byte 8-9   音频校验: 后续音频数据累加取低 16 位
byte 10..  音频文件数据
```

校验规则：

```text
headerChecksum = sum(bytes[0..6]) & 0xff
audioChecksum = sum(audioBytes[0..payloadLength-1]) & 0xffff
```

实现注意：

- 最后一包音频数据长度可能小于 240，以 `byte 6` 为准。
- `文件地址` 的大小端协议未明确，联调时需用真实设备抓包确认。文件大小字段已明确为大端；若文件地址无额外说明，建议协议层提供可切换字节序，避免后续固件差异导致大改。
- 收到地址不连续、包头错误、包长超过 240、校验失败时，当前文件进入 `checksum_failed` 或 `packet_invalid` 状态，并执行断点重传流程。
- 音频落盘时只写入 `byte 10` 后的有效音频数据，不写入 10 字节包头。

## 指令清单

### 常用指令

| 指令 | 名称 | App 数据 | 设备返回/上报 | 开发说明 |
| --- | --- | --- | --- | --- |
| `0x01` | 获取设备 SN | 无 | SN | 连接成功后优先调用 |
| `0x02` | 同步时间 | ASCII 时间，如 `20200102160255` | 无 | 连接初始化时调用 |
| `0x03` | 开始录音 | 无 | 文件名 | App 进入设备录音态 |
| `0x04` | 退出录音 | 无 | 文件名 + 文件大小 4 字节 + 录音时间 4 字节 + 录音模式 1 字节 | 文件大小字段按协议解析 |
| `0x05` | 获取本地录音列表 | 公版无数据；分页版为页码 + 每页数量，`pageSize=0` 表示不分页上传所有文件 | 文件名 + 文件大小 4 字节大端 + 文件时间预留 + 录音模式 1 字节 | 需兼容分页和非分页 |
| `0x06` | 文件列表上报结束 | 无 | 设备主动上报 | 列表拉取完成标记 |
| `0x07` | 获取本地文件数据 | 文件名无后缀 + 文件起始地址 4 字节 | 文件名无后缀 + 文件大小 4 字节 | 成功后音频从数据 UUID 上传 |
| `0x08` | 停止上传文件数据 | 无 | `0x09` | 校验失败或用户取消时使用 |
| `0x09` | 同步文件成功 | 不固定 | 设备主动上报 | 同步完成或停止成功，按状态机解释 |
| `0x0a` | 删除文件 | 文件名无后缀 | 无或失败上报 | 同步完成后可提示用户清理 |
| `0x0b` | 获取设备内存 | 无 | `0x0c` + `0x0d` | 设备会拆成剩余和总内存上报 |
| `0x0c` | 剩余内存 | 剩余内存 4 字节，单位 MB | 设备上报 | |
| `0x0d` | 总内存 | 总内存 4 字节，单位 MB | 设备上报 | |
| `0x0e` | 获取电量 | 无 | 0 到 100 | |
| `0x0f` | 录音状态 | 无 | 状态 1 字节 + 文件名 + 预留 4 字节 + 录音时间 4 字节 + 录音模式 1 字节 | 状态：`0x01` 录音中，`0x02` 暂停，`0x00` 无录音 |
| `0x10` | 暂停/恢复录音 | 无 | 同 `0x0f` | 设备自动识别暂停或恢复 |
| `0x12` | 软件版本 | 无 | 字符串，如 `0.0.1.0` | |
| `0x17` | 获取开关状态 | 无 | 多个设置项依次上报 | 见设置类指令 |
| `0x20` | 录音时间短，文件不保存 | 无 | 设备主动上报 | App 需提示用户 |
| `0x21` | 同步实时录音数据 | 无 | 音频从数据 UUID 上传 | 与分段录音结束配合 |
| `0x22` | 取消同步实时录音数据 | 无 | 无 | 录音结束后设备默认取消 |
| `0x29` | 文件传输终止 | 无 | 设备主动上报 | App 停止等待音频数据 |
| `0x2a` | 获取当前录音时长 | 无 | 当前录音时间 2 字节 | |
| `0x2b` | 获取录音模式 | 无 | 正常 `0x00`，通话 `0x01` | |
| `0x2c` | 关机 | 无 | 无 | 高风险操作，需二次确认 |
| `0x40` | 设备信息 | 无 | 见设备信息结构 | 初始化推荐调用 |
| `0x43` | 获取 MAC + SN | 无 | 蓝牙地址 6 字节 + SN | 可用于绑定设备 |
| `0x44` | 上报设备信息 | 无 | 剩余内存 4 字节 + 总内存 4 字节 + 充电状态 1 字节 + 电量 1 字节 | 设备周期主动上报 |

| 指令 | 名称 | 处理建议 |
| --- | --- | --- |
| `0xfe` | 文件列表获取失败 | 标记列表同步失败，允许重试 |

`0x40` 设备信息返回：

```text
剩余内存(4) + 总内存(4) + 充电状态(1) + 电量(1) + 是否在录音(1) + 软件版本(3) +
usb开关(1) + 录音模式(1) + 预留(1) + 预留(21) + 空闲关机时间(1) + 降噪开关(1) +
预留(1) + 录音分段时间(1)
```

充电状态：

| 值 | 含义 |
| --- | --- |
| `0x00` | 未充电 |
| `0x01` | 充电中 |
| `0x02` | 满电 |

## 核心流程

### 连接初始化

1. App 扫描广播并解析 MAC/SN。
2. 用户选择设备，App 建立 BLE 连接。
3. App 发现 Service 和 3 个 Characteristic。
4. App 订阅设备回复 Characteristic 和音频数据 Characteristic。
5. App 发送 `0x01` 获取 SN，发送 `0x43` 获取 MAC + SN，完成设备绑定校验。
6. App 发送 `0x02` 同步手机当前时间。
7. App 发送 `0x40` 获取设备信息，发送 `0x0f` 获取录音状态。
8. UI 进入已连接状态，展示电量、内存、录音状态、文件同步入口。

### 远程录音

开始录音：

```text
App -> 0x03
设备 -> 文件名
App -> UI 进入 recording 状态
```

暂停/恢复：

```text
App -> 0x10
设备 -> 录音状态 + 文件名 + 预留 + 录音时间 + 录音模式
App -> 根据状态刷新 UI
```

退出录音：

```text
App -> 0x04
设备 -> 文件名 + 文件大小 + 录音时间 + 录音模式
App -> 新增/更新待同步文件
```

异常：

- 设备上报 `0x20` 时提示“录音时间过短，文件未保存”。
- 设备上报 `0xf9` 时提示“录音失败”，并刷新 `0x0f` 状态。

### 文件列表同步

公版协议：

```text
App -> 0x05
设备 -> 多条文件记录
设备 -> 0x06
```

分页协议：

```text
App -> 0x05 [pageIndex, pageSize]
设备 -> 当前页文件记录
设备 -> 0x06
App -> 如本页数量达到 pageSize，继续请求下一页
```

兼容策略：

- 默认优先使用分页：`pageIndex=0`，`pageSize=20`。
- 如果设备返回失败 `0xfe` 或明显不支持分页，可降级为无数据 `0x05`。
- 文件名不带后缀时，本地统一补 `.sbc` 保存。
- 以 `deviceId + fileNameNoExt` 去重。

### 文件下载同步

正常流程：

```text
App -> 0x07 [fileNameNoExt + startAddress]
设备 -> 文件名无后缀 + 文件大小 4 字节
设备 -> audio characteristic 连续上传音频包
App -> 校验每包并追加写入 .sbc
设备 -> 0x09 或 0x29
App -> 标记 downloaded
```

下载状态机：

```text
download_pending
  -> downloading
  -> downloaded
  -> cloud_sync_pending
  -> cloud_syncing
  -> synced

downloading
  -> checksum_failed
  -> stopping_for_retry
  -> retry_pending
  -> downloading

downloading
  -> failed
```

断点续传流程：

1. App 收到音频包，发现包头、地址、包长或校验异常。
2. App 停止写入当前异常包。
3. App 记录最后一个已成功写入的地址：`resumeAddress = syncedBytes`。
4. App 下发 `0x08` 停止上传。
5. 设备返回 `0x09` 后，App 重新下发 `0x07 [fileNameNoExt + resumeAddress]`。
6. 继续接收、校验、追加写入。
7. 同一文件连续失败超过阈值后标记 `failed`，保留 checkpoint 供用户手动重试。

推荐阈值：

| 参数 | 建议值 | 说明 |
| --- | --- | --- |
| 单指令响应超时 | 5 秒 | 常规控制指令 |
| 文件列表等待超时 | 10 秒 | 到 `0x06` 为止 |
| 音频包空闲超时 | 8 秒 | 下载中长时间无音频包 |
| 单文件自动重试 | 3 次 | 超过后用户手动重试 |
| 连续校验失败 | 2 次 | 触发断开重连排查 |

### 实时录音数据同步

实时同步使用 `0x21` 开启，音频仍通过音频数据 Characteristic 上传。

注意事项：

- 设备默认每隔一段时间进行录音分段。
- 实时转写场景下，设备自动结束录音会上报 `0x26`，且不会自动开始下一段录音；App 转写完后需要主动再次下发开始录音 `0x03`。
- App 最终同步到的实时录音数据可能比设备本地文件多几帧 SBC 数据。原因是设备本地以 512 字节扇区保存，最后不足 512 字节的数据可能未保存到本地文件。这几帧不影响整体录音效果。
- 每次录音结束后设备会默认取消实时同步，因此 `0x22` 可以不发，但 App 状态机仍应支持主动取消。

## 本地存储与云端同步

### 本地文件

建议保存路径：

```text
ApplicationDocuments/
  recording_cards/
    <deviceId>/
      files/
        <fileNameNoExt>.sbc
      metadata/
        <fileNameNoExt>.json
```

metadata 至少保存：

- 设备 SN、MAC、固件版本。
- 文件名、文件大小、录音时长、录音模式。
- 已下载字节数、校验失败次数、最近错误。
- 本地 `.sbc` 路径、转码后文件路径。
- 云端 memory id 或 knowledge id。
- 同步状态和更新时间。

### 云端衔接

现有 mobile 端已有创建记忆接口：

```text
POST /api/v1/organize/memories
```

当前接口适合先保存录音元数据和转写文本；如果需要云端保存真实音频文件，还需要确认后端是否已有文件上传接口，或新增音频上传能力。

设备录音建议 metadata：

```json
{
  "sync_source": "recording_card",
  "device_sn": "VoRecAi_000020",
  "device_mac": "xx:xx:xx:xx:xx:xx",
  "device_firmware": "0.0.1.0",
  "recording_file_name": "REC0001",
  "audio_file_name": "REC0001.sbc",
  "audio_codec": "sbc",
  "sample_rate": 16000,
  "channels": 1,
  "sample_format": "s16p",
  "recording_mode": 0,
  "duration_seconds": 120,
  "file_size_bytes": 123456,
  "local_audio_path": "/app/documents/recording_cards/.../REC0001.sbc"
}
```

如要接入现有“录音记忆”体验，需补齐两点：

- 端侧或服务端将 `.sbc` 转为可播放格式，并生成转写文本。
- 创建记忆时使用 `kind=audio`，`source=录音卡`，metadata 标记 `sync_source=recording_card`，避免和手机麦克风录音混淆。

## UI 调试页建议

联调阶段建议先做一个隐藏或开发态入口，功能包括：

- 扫描设备：展示 SN、MAC、RSSI、广播原始数据。
- 连接状态：展示服务发现、通知订阅、MTU/连接参数。
- 设备信息：SN、MAC、固件、电量、充电状态、内存、录音模式、录音状态。
- 录音控制：开始、暂停/恢复、结束、当前时长。
- 文件列表：文件名、大小、时长、模式、同步状态。
- 文件同步：开始同步、暂停/取消、重试、删除设备文件。
- 协议日志：按时间展示 TX/RX 指令、音频包地址、校验结果、错误码。

协议日志建议字段：

```text
timestamp, direction, channel, command, payloadHex, fileName, address, length, result, error
```

## 设备详情页

截图中的“我的设备”页应作为正式业务页，与调试页分开。它更偏用户侧配置和状态概览，建议在设备已绑定后进入。

### 页面结构

1. 顶部导航栏
   - 标题：`我的设备`
   - 左侧返回按钮
2. 设备概览卡
   - 设备名称：如 `LY02`
   - SN：如 `QHL2000018`
   - 设备主图
   - 电量百分比：如 `71%`
3. 基础信息卡
   - 内存：如 `3.7G / 3.7G`
   - 录音模式：如 `note`
   - 固件升级：如 `v0.0.1(1008)`
4. 参数设置卡
   - 降噪等级：关 / 低 / 中 / 高
   - 分段录音时长：如 `2小时`
   - 后续可继续扩展 USB 开关、关机时间、是否生成 WAV 等条目

### 字段映射

| 页面字段 | 数据来源 | 协议/接口 |
| --- | --- | --- |
| 设备名称 | App 绑定名或后端别名 | 本地缓存或业务接口 |
| SN | 设备 SN | `0x01` / `0x43` |
| 电量 | 设备电量 | `0x0e` / `0x44` |
| 内存 | 剩余内存 + 总内存 | `0x0b` / `0x0c` / `0x0d` / `0x44` |
| 录音模式 | 当前录音模式 | `0x1d` / `0x2b` / `0x40` |
| 固件版本 | 软件版本 | `0x12` / `0x40` |
| 降噪等级 | 降噪开关 | `0x15` / `0x17` / `0x40` |
| 分段录音时长 | 录音分段时间 | `0x42` / `0x40` |

### 交互建议

- 设备详情页进入后先刷新一次 `0x40`、`0x0e`、`0x0f`、`0x12`、`0x17`。
- 页面前台驻留时，内存、电量、录音状态建议周期刷新。
- 参数项点击后进入二级设置页或底部弹层，不建议直接在列表里硬切换。
- 固件升级当前协议未定义，建议先作为独立入口和占位态处理，待 OTA 协议补齐后再接入。

### 页面状态

- 未连接：展示离线状态和重连按钮。
- 连接中：展示加载态。
- 已连接：显示实时数据。
- 同步中：保留设备信息，列表项可禁用避免误操作。
- 异常：电量/内存/版本等局部失败时，页面不要整页报错，按字段降级显示。

## 权限与平台事项

Android：

- 需要蓝牙扫描、连接权限；低版本系统还可能需要位置权限才能扫描 BLE。
- 需要前台运行策略，避免大文件同步时应用退后台导致连接中断。
- 如使用文件转码或实时转写，需要评估麦克风、存储和后台任务限制。

iOS：

- 需要蓝牙权限描述。
- BLE 后台运行能力需按产品需求决定是否开启；若不开启，App 退后台应暂停或取消同步并保存 checkpoint。
- iOS 对 BLE 长连接和后台传输限制更严格，必须用真机验证。

## 测试计划

### 协议单元测试

- App 指令编码：`0x01` 编码为 `55 aa 01 01`。
- 设备指令解码：示例 SN 返回包可正确解析为 SN。
- 音频包校验：正常包通过，错误包头、错误长度、错误头校验、错误音频校验均失败。
- 文件地址解析：覆盖大小端配置。
- 文件列表解析：覆盖分页和非分页格式。

### BLE 集成测试

- 扫描能发现目标设备并正确展示 SN/MAC。
- 连接后能发现 1 个 Service 和 3 个 Characteristic。
- 通知订阅成功后能收到设备主动上报。
- 断开重连后状态恢复，未完成文件可继续同步。

### 文件同步测试

- 小文件完整下载，大小与设备返回一致。
- 大文件连续下载，中途锁屏、切后台、断开蓝牙后可恢复。
- 人为制造校验失败，App 发送 `0x08`，收到 `0x09` 后从断点 `0x07` 重传。
- 最后一包小于 240 字节时文件大小正确。
- 同一文件重复同步不会创建重复本地记录。
- 同步完成后删除设备文件，失败时不会删除 App 本地文件。

### 录音控制测试

- 开始录音返回文件名。
- 暂停/恢复返回状态正确。
- 结束录音返回文件名、大小、时长、模式。
- 录音过短时收到 `0x20` 并提示文件未保存。
- 录音失败时收到 `0xf9` 并退出录音态。

## 联调检查表

设备侧需确认：

- 文件地址 4 字节大小端。
- 文件名长度、编码和是否固定格式。
- 文件列表单条记录的精确字段长度，尤其“文件时间预留”的字节数。
- `0x07` 请求中的文件起始地址大小端。
- `0x09` 与 `0x29` 在文件完整传输完成时的上报顺序。
- 音频数据 Characteristic 是否要求开启 notify 或 indicate。
- 是否支持 MTU 协商；不同 iOS/Android 机型每包是否稳定 250 字节。
- 分页版 `0x05` 在最后一页如何判断结束。

App 侧需确认：

- BLE 插件选型和 Android/iOS 权限配置。
- `.sbc` 是否端侧转码，还是上传服务端转码。
- 云端是否需要保存真实音频文件；若需要，后端文件上传接口和字段需补齐。
- 设备文件同步完成后是否默认删除，还是由用户手动删除。
- 实时录音数据是否纳入第一期范围。

## 推荐开发顺序

1. 实现协议编解码和单元测试，不接真实 BLE。
2. 实现 BLE 扫描、连接、服务发现、通知订阅。
3. 打通基础指令：`0x01`、`0x02`、`0x40`、`0x0f`、`0x0e`。
4. 打通文件列表：`0x05`、`0x06`、失败码 `0xfe`。
5. 打通单文件下载：`0x07`、音频包校验、`.sbc` 落盘、`0x09`/`0x29` 完成。
6. 实现校验失败后的 `0x08` 停止和断点续传。
7. 接入云端记忆创建和本地 metadata。
8. 实现录音控制：`0x03`、`0x04`、`0x10`、`0x20`、`0xf9`。
9. 再评估实时同步 `0x21`、设备参数设置和删除文件。

## 里程碑验收

### M1：设备连接与基础信息

- 能扫描、连接、展示 SN/MAC、电量、内存、固件版本。
- 断开重连后 UI 状态正确。

### M2：文件列表与下载

- 能获取设备文件列表。
- 能下载一个完整 `.sbc` 文件并校验大小。
- 下载失败可重试。

### M3：可靠同步

- 支持断点续传。
- 支持大文件和中断恢复。
- 支持本地 metadata 和云端记忆创建。

### M4：录音控制

- App 可控制设备开始、暂停、恢复、结束录音。
- 结束录音后自动进入文件同步。

### M5：体验完善

- 支持批量同步、同步进度、错误提示、删除设备文件。
- 根据产品需求支持实时录音数据同步和转写。
