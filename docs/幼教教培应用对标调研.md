# 幼教 / 教培 / AI 助手应用对标调研

> 版本 v1.0 ｜ 2026-10-10 ｜ **范围：仅调研**（不改 `frontend/`、`internal/`、`migrations/`）
> 检索时点：2026-10-10 ｜ 数据来源见文末「来源」

---

## 0. 三条结论（先说）

1. **赛道形态正在换，你的方向是对的。** Famly（丹麦，10,000+ 园所、100 万家长与教师用户）在 **2026-10-08** 重新发布为「主动型 ECE 助手」，官方叙事原话是：「**传统幼教软件本质上只是一个报名和账单的数据库**」。睿乐刚砍掉的「服务空间」正是那个数据库；分身 + Agent 模块指向的正是新形态。

2. **已经有先行者落地，而且做得比我们想的更狠。** illumine（4,000+ 园所 / 60+ 国家）**2026-09-17** 发布三个 AI Agent，其中一个就是**招生 Agent**（非工作时间接电话、预约参观、安排跟进）。Famly 的 Frankie 做「早晨简报 + 主动标记该关注的事」。我们清单里第 1（招生线索跟进）、第 4（续费与流失预警）、第 9（经营日报）全在这个射程内。

3. **真正该抄的是两条约束，不是功能。** ① 助手**不得在未获用户确认前执行动作**（Famly 明确写进产品原则）；② **儿童数据不得用于训练共享模型 + 租户隔离 + 审计日志**（illumine 的 Responsible AI 架构）。功能能抄，约束抄错会出事。

## 1. 口径：什么叫「做得好」

三条可验证标准，缺一条就不算：

| 标准 | 问法 |
|---|---|
| **一线留存** | 老师 / 顾问愿不愿意每天主动打开（不是园长买不买） |
| **输入成本** | 一次录入要几步；能不能边说边录、边拍边录 |
| **采用速度** | 家长 / 员工上手需不需要培训 |

> 反例提醒：腾讯元宝月活 0.41 亿，**用户留存率仅 38%** —— 功能全 ≠ 留存高。

## 2. 国际同类（真正的标杆，按「值得抄」排序）

### 2.1 Famly / Frankie ★ 最值得看

| 项 | 内容 |
|---|---|
| 规模 | 10,000+ 园所；100 万家长与教师；丹麦 2013 年创立 |
| 时点 | **2026-10-08 重新发布**为「proactive ECE assistant」 |
| 形态 | 一个应用内助手 Frankie，**从园所自己的数据出发** |

**Frankie 干的事**：回答问题、起草消息、**建立并调度周期任务**、回答园所政策、**早晨简报**、**主动标记需要关注的事**（逾期余额 / 失败付款 / 缺失付款信息）、学习个人偏好并按历史请求的逻辑复用。

**一条硬约束**（原文）：助手**在未先获得用户确认前，绝不执行动作**。

**它引用的行业痛点数据**（Famly 2026 ECE Field Survey）：89% 每周至少加班一次；62% 每周加班 3 天以上（2025 年为 53%）；51% 持续倦怠；77% 每周仍能感到工作乐趣。

- **抄**：早晨简报、主动标记、确认后执行、把叙事钉在「把时间还给老师」。
- **不抄**：面向欧美的补贴核算、130+ 语言实时翻译等本地化。

### 2.2 illumine ★ 竞品最直接

| 项 | 内容 |
|---|---|
| 规模 | 4,000+ 园所；60+ 国家；主打多园连锁 |
| 时点 | **2026-09-17** 发布三个 AI Agent |

| Agent | 做的事 | 对应睿乐 |
|---|---|---|
| **Enrollment Agent** | 非工作时间接电话、**预约参观**、安排跟进 | ① 招生线索跟进 |
| **Billing Agent** | 聊天式取财务报表、趋势、合规数据 | ⑨ 经营数据日报 |
| **Activity Agent** | **扫描教室照片自动起草观察记录**，老师可加语音输入共创 | ⑦ 幼儿成长报告 + 采集键 |

**架构原则**：Privacy by Design；**客户数据不用于训练公共或共享模型**；只用任务所需的上下文；租户级数据隔离；细粒度 RBAC；完整审计日志。

- **抄**：Activity Agent 的「照片 → 草稿，老师用语音补充」（这正是「采集键 + 整理」的组合）；AI 只做案头活。

### 2.3 Brightwheel ★ 采用率标杆

美国单体园 / 小连锁（5 园以内）的默认答案。**它为什么赢**，原话值得记：

> 「parent adoption is the actual job」——家长采用才是真正的活儿；
> 「the activity feed works like the apps families already live in」——信息流长得像家长本来就在用的 App；
> 「using it doesn't feel like a chore」——**用起来不像是在干额外的活**。

老师侧也一致：**课堂内界面比同类产品简单**，所以老师愿意用。

- **抄**：「不让人觉得在干额外的活」；**老师端必须比管理端更简单**。
- **不抄**：超过 3–4 个园区就明显不够用（多园报表弱）。

### 2.4 Lillio（前 HiMama）

日报（daily report）全品类最强：**learning stories 把每条观察绑定到发展领域**，一年积成作品集，并对齐 NAEYC / EYLF / ELECT 等框架。

- **抄**：**观察 → 成长领域 → 作品集** 这条链。睿乐的「幼儿成长报告」就该按这条链做，而不是每次现写一段。

### 2.5 Procare / LineLeader / ChildcareCRM

- **Procare**（35 年，多园与加盟）：招生漏斗最完整 —— 自定义线索表单、阶段流水线、**转化率与 time-in-stage**（每条线索在各阶段停留多久）。
- **LineLeader / ChildcareCRM**：招生专项，含线索培育与营销自动化。
- **抄**：**time-in-stage** 这个指标——「卡在哪一步」从此可量化。

## 4. 国内同类

### 4.1 家园共育（家长侧）

| 应用 | 规模 | 特点 |
|---|---|---|
| **掌通家园** | 覆盖 2900+ 县区、近 11 万园所、3100 万家长；家长端 DAU 约 600 万、园丁端 DAU 约 50 万 | B2B2C：靠硬件（人脸识别签到机、晨检机）+ 视频直播拿家长流量 |
| **智慧树** | 服务 12 万+ 幼儿园、2800 万家长 | 班级动态 / 相册 / 表现点评 / 成长日记 |
| 贝聊 / 掌心宝贝 / 一起长大 / 小小时光 | 中小 | 同质化较高 |

> 值得注意的一处**反例**：掌通家园有部分地区园所向家长**强制收取 App 使用费**，被教育部门认定为违规收费。**面向家长收费这条线不要碰。**

### 4.2 老师侧（最接近睿乐整理模块）

**幼师口袋**：一键生成幼儿**观察记录**、**家园联系册**等常用文档；教案 / 环创 / 区角素材库（五大领域 × 年龄段）；云收藏。定位是「减文案案头工作」。

- **抄**：它就是国内把「老师最烦的文书」做成核心卖点的样板，且验证了两件事——**素材要能直接复用**、**文档要一键生成**。

### 4.3 教培招生 CRM（最接近招生链路）

| 产品 | 与睿乐相关的点 |
|---|---|
| **校管家** | 小竹通 AI 招生助手（活动方案 / 文案）+ **AI 智能外呼**（拨号 + 录音 + 语音转写 + **沟通记录生成** + 跟进过程追踪） |
| 校宝在线 | 线索按来源 / 兴趣标签分类，与学员档案联动 |
| 爱耕云 | 渠道活码 + 扫码自动分配跟进人 |
| 小鹅通 | 线上线索为主（体验课报名 / 问卷） |
| 学邦 | 线下线索（转介绍 / 入学测试）精准度高 |

- **抄**：AI 外呼那一段 —— **录音 → 转写 → 沟通记录**这条链，是睿乐「到访谈单复盘」的现成同类；校管家已经把它卖成卖点。
- **参考**：招生漏斗看 **渠道来源 × 转化阶段** 的交叉，而不是看线索总量。

### 4.4 同形态（AI 助手门面）

| 产品 | 月活 | 形态结论 |
|---|---|---|
| **豆包** | 2.26 亿 | 赢在「**具体的人**」而非「抽象工具」。行业分析：千问 / 元宝 / 文心被用户当成工具，只有需要功能时才打开；豆包被当成一个角色，才有日常粘性 |

| 腾讯元宝 | 0.41 亿 | **留存仅 38%**，界面复杂度高 —— 反面教材 |

> 一句可直接引用的话：**「AI 这东西没有最好，只有最适合」**——但形态层面已经分出胜负：**拟人化 > 工具化**。

## 6. ⚠️ 两条硬约束（别踩）

### 6.1 助手动作必须「先确认，后执行」

Famly 把这条写成了产品原则。它同时解决三个问题：合规风险、误操作成本、用户信任。**睿乐的分身写回任何东西（建待办 / 改字段 / 发消息）都应遵守这一条。**

### 6.2 幼教场景的 AI 红线（引自 childcare 行业评测的明确主张）

**可以**：起草通知 / 简报、**总结老师自己写下的记录**、标记逾期账目与未完成事项。

**绝对不可以**：

1. 对儿童的安全、行为、发育**做决策**；
2. 对儿童做**人脸识别或生物识别**；
3. 把儿童照片与数据用于**训练第三方模型**。

配套的数据侧要求（illumine 的做法）：**租户级隔离 + 角色可见性 + 审计日志**，且只用任务所需的上下文。

> 这三条与睿乐现有能力不冲突，但**必须写进 Agent 模块的验收标准**，否则将来是产品事故而不是 bug。

---

## 7. 建议的三个动作

1. **把上一条红线写进《Agent 模块设计方案》的验收标准**——AI 只做案头、不做保育判断、不训模型。这是最低成本、最高收益的一次改动。
2. **给分身补一个「早晨简报」**（对标 Famly）。我们已有现成底座：经营日报（整理模板）+ 到访谈单复盘（daily）+ 风险名单。合并成一屏，早上推一次即可，不需要新表。
3. **把 Procare 的 time-in-stage 补进招生链路指标**——「卡在哪一步」从形容词变成数字。落点是招生整理的输出栏目，不是新功能。
