# 整理模板 · 操作描述（样例）

> **样例对象**：平台模板 **谈单复盘**（`key = visit_review`，日更 20:00）
> **形态**：与现有「报告预设」（`markdown_template`）**并列的第二份 Markdown**，随模板一起发布、随 `template_version` 一起冻结。
> **目的**：把「这个模板在整理过程中能做哪些动作、每项动作谁说了算」从**代码里**搬进**模板里**，让管理员可读可改，运行时按档执行。
> **状态**：最小样例，供评审；未落库、未接线。

---

## 一、三档定义

| 档位 | 一句话 | 运行时的做法 | 使用者看到什么 |
|---|---|---|---|
| **低档** | 模型自行可改 | 执行完直接返回，不打断 | 只有最终产出 |
| **中档** | 要出 tip | 执行完给一条提示，附「撤销」 | 产出 + 一条可撤销提示 |
| **高档** | 用户手动确认 | 只出草稿，点了才执行 | 产出 + 一张待确认卡 |

**判定规则**

1. **默认高档**：未在本文件列出的操作，一律按高档处理。宁可多问一次，不静默越权。
2. **不自行降级**：模型想执行高档操作时，必须出确认卡；**不允许**把高档操作改写成低档悄悄做掉。
3. **按版本冻结**：执行时读的是**任务发起那一刻的模板版本**，管理员事后改档位不影响已在跑的整理。

---

## 二、低档｜模型自行可改

只新增、且只写本模板自己的产出，不触碰别处已有数据。

| 操作 | 键 | 落点与说明 |
|---|---|---|
| 生成产出正文 | `output.create` | `organize_outputs.content`。本模板的唯一必需操作，现状已如此 |
| 生成一句话摘要 | `output.summary` | `organize_outputs.source_summary`。开头一句，≤30 字 |
| 生成标签与场景 | `output.tags` | `organize_outputs.metadata`。取自模板 `spec.tags` / `spec.scene` |
| 生成依据引用 | `output.citations` | `organize_outputs.citations`。关键事实标 `[M1]`、`[M2]` |
| 生成「信息缺口与待确认项」 | `output.open_questions` | 只落正文，不单独入库 |
| 生成覆盖度自评 | `output.coverage` | `organize_outputs.metadata.coverage`。有多少条记忆没读到，如实写 |

---

## 三、中档｜出提示后可执行

会新增到别处，但**不修改已有内容**；每条都带撤销。

| 操作 | 键 | 落点与说明 |
|---|---|---|
| 新建待办 | `reminder.create` | `service_reminders`。把「下一步」清单落成待办。提示「本次生成 N 条待办 · 撤销」；**同一模板同一时段已生成过则跳过并说明**（防重复刷屏） |
| 归属产出到目标服务 | `output.assign` | `service_context_sources`。配置里已指定目标服务时自动归属，提示「已归属到「果果家」· 改归属」 |
| 追加记忆标签 | `memory.tag_append` | `memories.metadata.tags`。**只追加不覆盖** |
| 标记发现项 | `discover.mark` | `organize_discover`。供「发现」页签聚合 |

---

## 四、高档｜需用户手动确认

覆盖、删除，或触及家长 / 学员信息。

| 操作 | 键 | 落点与说明 |
|---|---|---|
| 覆盖同名产出 | `output.overwrite` | 同配置重跑覆盖旧版；旧版进版本记录，确认卡展示改动行数 |
| 抽取并写入档案条目 | `fact.write` | `service_facts`。谈单复盘的三个字段（卡点 / 意向课程 / 决策人）**现状走的就是提案卡**，等价于高档；如果想让它自动写，必须在此显式声明并说明理由 |
| 修改已有待办 | `reminder.update` | 改截止时间 / 负责人 / 状态；确认卡逐条列出改动前后 |
| 改写或合并已有记忆正文 | `memory.rewrite` | `memories.content`。本期**默认不做**；一旦开通必须逐条确认 |
| 删除内容 | `memory.delete` · `output.delete` · `reminder.delete` | 三类删除一律确认，且为软删 |

---

## 五、硬红线（不设档位，恒不可执行）

以下三条**不参与分档**——无论模板怎么写、管理员怎么配，都不执行：

- `outreach.send` —— **对家长 / 学员直接发送任何内容**；草稿一律先经老师确认。
- `child.judgement` —— 对儿童做安全 / 行为 / 发育判断。
- `model.train` —— 把家长 / 学员数据用于训练第三方模型。

---

## 六、这份文件带来的两个直接变化

1. **「模型能自己做什么」从代码常量变成模板数据** —— 换一个模板就换一套授权，不用发版。
2. **中档是新的一档，填的是中间的空白** —— 现在只有「自动做」和「问一次」两端；大量动作（建待办、归属、追加标签）其实属于「做了也行、但得让人知道」，这一档专门承接它。

# 以下是实现说明，不进模板本体

## 附 A · 确定性解析规则

与 `markdown_template` 的编译方式（`organize_template_compiler.go`）保持同一种风格：**纯字符串解析，不花 LLM 调用**。

| 元素 | 规则 |
|---|---|
| 档位小节 | 二级标题，形如 `## 二、低档｜模型自行可改`；取「｜」前的档位词映射为 `low` / `mid` / `high` |
| 操作条目 | 该小节内的表格行；第 1 列 = 展示名，第 2 列 = 键（反引号内），第 3 列 = 说明 |
| 硬红线 | `## 五、硬红线` 小节内的列表项，解析为 `forbidden` |
| 校验 | 键必须唯一；同一键不得同时出现在两档；未列出的键运行时按 `high` 处理 |

产物建议落到 `organize_templates.spec.operations_policy`（JSONB，**不必加列**），形如：

```json
{
  "version": "v1",
  "default_tier": "high",
  "operations": [
    {"key": "output.create", "label": "生成产出正文", "tier": "low", "target": "organize_outputs.content"},
    {"key": "reminder.create", "label": "新建待办", "tier": "mid", "target": "service_reminders"},
    {"key": "fact.write", "label": "抽取并写入档案条目", "tier": "high", "target": "service_facts"}
  ],
  "forbidden": ["outreach.send", "child.judgement", "model.train"]
}
```

模板本体另加一列 `operations_md TEXT`（照 `001015_organize_template_markdown.up.sql` 给 `markdown_template` 加列的先例），`organize_template_versions.snapshot` 同步带上，保证版本冻结。

## 附 C · 定档建议（供讨论，未拍板）

| 操作 | 建议档 | 理由 |
|---|---|---|
| 生成产出正文 / 摘要 / 标签 / 引用 | 低 | 现状即如此，且只影响自己的产出 |
| 新建待办 | 中 | 价值高但易重复；提示 + 撤销足够，不必每次都拦 |
| 归属产出到服务 | 中 | 改的是归属关系，可改回 |
| 追加记忆标签 | 中 | 只追加，风险低 |
| 覆盖产出 / 改已有待办 / 改删记忆 | 高 | 不可逆或影响别处 |
| 写服务档案（家长、学员信息） | 高 | 合规敏感，逐字段勾选 |
| 对家长发送 | 禁止 | 红线，不入档位 |
