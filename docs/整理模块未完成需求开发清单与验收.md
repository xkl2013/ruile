
## 2. 实施原则

1. **增量迁移**：只新增表、字段和接口，不删除旧字段，不立即删除旧 API。
2. **默认关闭**：新模板引擎、SSE、自由整理要求等新链路通过开关控制。
3. **先观察再强制**：先记录新旧结果差异和失败率，再切换默认链路。
4. **历史资源保护**：历史产物即使没有模板版本、结构化字段或引用，也必须可以查看。
5. **每包独立验收**：上一项验收通过后再进入下一项，不跨阶段叠加风险。
6. **前后端同一契约**：字段定义、模板版本、任务状态和错误语义由后端返回，前端不再复制业务常量。
7. **失败可回退**：模型失败、模板错误、SSE 断开、字段缺失时，都要保留现有可用路径。

## 3. 推荐实施顺序

### 5.3 后端接口需求

建议新增受 `SystemAdmin` 保护的接口：

| 方法 | 接口 | 用途 |
| --- | --- | --- |
| `GET` | `/api/v1/system/admin/organize/templates` | 模板列表 |
| `POST` | `/api/v1/system/admin/organize/templates` | 新建模板 |
| `GET` | `/api/v1/system/admin/organize/templates/:key` | 模板详情 |
| `PUT` | `/api/v1/system/admin/organize/templates/:key` | 保存草稿 |
| `POST` | `/api/v1/system/admin/organize/templates/:key/preview` | 试跑 |
| `POST` | `/api/v1/system/admin/organize/templates/:key/publish` | 发布版本 |
| `POST` | `/api/v1/system/admin/organize/templates/:key/disable` | 停用模板 |
| `GET` | `/api/v1/system/admin/organize/templates/:key/versions` | 版本列表 |
| `GET` | `/api/v1/system/admin/organize/templates/:key/versions/:version` | 版本详情 |
| `POST` | `/api/v1/system/admin/organize/templates/:key/rollback` | 从历史版本创建新版本 |

接口规则：

- `key` 创建后不可修改。
- 草稿保存不影响前台运行。
- 只有通过校验并发布的版本才可以被用户侧读取。
- 停用模板后，历史任务和历史产物仍可查看。
- 发布、停用、回滚必须记录操作人、时间和变更说明。

## 7. R3：结构化字段筛选和引用回溯

### 7.1 目标

让整理产物从“能看到字段”升级为“能按字段查找，并能从引用回到原始记忆”。

### 7.2 字段契约

模板发布时声明字段定义：

```json
{
  "fields": [
    {
      "key": "risk_level",
      "label": "风险等级",
      "type": "enum",
      "filterable": true,
      "sortable": true,
      "source": "model",
      "options": ["高", "中", "低"]
    }
  ]
}
```

规则：

- `key` 发布后不可修改；语义变化必须新建字段。
- `label` 可以修改，但必须保留 key。
- `source=derived` 的字段由系统计算，不依赖模型是否返回。
- `source=model` 的字段不能用虚构值填充；无依据时返回“待补充”或空值。
- 历史产物没有字段时仍然显示，但不参与字段 facets。

### 7.3 API 和前端需求

- [ ] 扩展 `GET /api/v1/organize/outputs`：
  - [ ] 支持模板、场景、配置、状态过滤；
  - [ ] 支持 `field[key]=value` 字段过滤；
  - [ ] 支持字段排序；
  - [ ] 支持分页和稳定排序。
- [ ] 增加 `GET /api/v1/organize/outputs/facets`：
  - [ ] 返回当前查询范围内可用字段、选项和数量；
  - [ ] 历史空字段不产生空选项。
- [ ] 产物列表增加字段筛选器和筛选结果计数。
- [ ] 从详情返回列表时保留关键词、字段筛选、排序和分页状态。
- [ ] 引用 `[M1]` 或引用卡片点击后打开对应记忆详情/预览。
- [ ] 原始记忆被删除时，引用显示“原记忆已删除”，不报错、不跳转到错误页面。
- [ ] 对引用的租户、用户和权限重新校验，不能通过引用 ID 越权读取记忆。

### 7.4 验收标准

| 编号 | 验收项 | 验证方式 |
| --- | --- | --- |
| R3-AC-01 | 新发布模板至少声明两个可筛选字段，否则无法发布 | Admin 发布用例 |
| R3-AC-02 | 产物列表可以按字段值过滤，结果数量正确 | API 集成测试 + 前端手工验收 |
| R3-AC-03 | facets 数量与当前查询结果一致 | API 测试 |
| R3-AC-04 | 字段筛选、关键词、排序和分页可以组合使用 | API 参数组合测试 |
| R3-AC-05 | 从详情返回后筛选条件完整保留 | 浏览器用例 |
| R3-AC-06 | 点击引用可以定位到正确原始记忆 | 前端联调 |
| R3-AC-07 | 原始记忆删除后，引用保留编号并显示缺失状态 | 删除记忆后的回归用例 |
| R3-AC-08 | 跨租户、跨用户引用访问均返回无权限或不存在 | 权限测试 |
| R3-AC-09 | 没有 fields/citations 的历史产物仍能正常查看和全文搜索 | 历史数据回归 |

**R3 完成定义**：用户可以不打开正文，依靠字段判断产物主题和规模，并从引用回到原始记忆。

## 8. R4：任务 SSE 实时进度

### 8.1 目标

将当前配置详情页的轮询进度升级为事件驱动，同时保留轮询作为断线和旧浏览器回退。

### 8.2 事件契约

`GET /api/v1/organize/jobs/:id/events` 至少支持：

| 事件 | 必填数据 |
| --- | --- |
| `snapshot` | job 完整状态、stage、progress |
| `progress` | job ID、status、stage、progress、summary |
| `completed` | output ID、status、summary |
| `fallback` | output ID、降级原因 |
| `failed` | error code、可重试标记 |
| `canceled` | 取消时间 |
| `heartbeat` | 服务端时间 |

### 8.3 开发清单

- [ ] 明确事件 JSON schema 和错误码。
- [ ] 支持客户端断线后重连。
- [ ] 支持同一用户只读取自己有权限的 job。
- [ ] 任务完成、失败、取消后主动关闭事件流。
- [ ] 配置详情页优先使用 SSE。
- [ ] SSE 连接失败或超时后自动回退到现有轮询。
- [ ] 工作台运行中任务显示统一状态，不重复创建任务。
- [ ] 页面离开时关闭事件连接。

### 8.4 验收标准

| 编号 | 验收项 | 验证方式 |
| --- | --- | --- |
| R4-AC-01 | 连接后 3 秒内收到一次 `snapshot` 或明确错误 | Handler 集成测试 |
| R4-AC-02 | 任务进度变化能按顺序推送，不倒退 | 异步任务测试 |
| R4-AC-03 | 完成、降级、失败、取消分别收到终态事件 | 状态机测试 |
| R4-AC-04 | 断开重连后可以恢复最新状态，不重复显示旧进度 | 浏览器断网/重连测试 |
| R4-AC-05 | SSE 不可用时，页面自动回退到轮询，用户仍能看到终态 | 前端故障注入 |
| R4-AC-06 | 无权访问的 job 不会通过事件流泄露状态或产物 ID | 权限测试 |
| R4-AC-07 | 页面卸载后没有遗留连接和重复刷新定时器 | 浏览器资源检查 |

**R4 完成定义**：任务执行中页面可以实时更新，网络或浏览器不支持 SSE 时不影响任务最终可见性。

## 9. R5：自定义整理要求和歧义确认

> 本项对应原 PRD Q8，当前属于待拍板能力。现行产品范围可以继续只支持“选模板 + 定范围”。只有确认需要自由描述后，才启动本项。

### 9.1 目标

用户输入“把这周的家长沟通记录整理成复盘”这类自然语言后，系统先解析成结构化整理要求，再让用户确认，确认后才创建正式任务。

### 9.2 开发清单

- [ ] 增加默认关闭的 `organize.custom_requirement.enabled`。
