# 整理模块现状与文档索引

> 文档基线：2026-10-05  
> 事实来源：当前仓库代码、路由、接口、迁移和最近提交。  
> 适用范围：`frontend/src/views/organize`、`frontend/src/api/organize`、`internal/application/service/organize*`、`internal/handler/organize*`、`internal/types/organize*`、`admin/src/views/AdminCourses.vue`。

## 1. 先看结论

当前“整理”不是单一的 AI 报告页面，而是由四块能力组成：

| 能力 | 当前定位 | 主要入口 |
| --- | --- | --- |
| 整理工作台 | 管理可复用整理配置、选择模板、发起任务 | `/platform/organize/hub` |
| 记忆 | 录入、上传、编辑和处理用户自己的记忆 | `/platform/organize/memory` |
| 我的整理 | 查看整理产物、按场景搜索和筛选 | `/platform/organize/mine` |
| 发现 | 浏览已发布内容、课程和公开知识库 | `/platform/organize/discover` |

其中：

- **整理配置**是用户拥有的可复用规则，不是单次产物。
- **整理任务**是一次执行记录，绑定配置、模板版本、输入记忆和产物。
- **整理产物**可以查看字段、引用和正文，也可以分配到服务空间；后端保留更新接口，但当前产物详情页主要承担查看和归属。
- **发芽**已经收敛为一种整理模板/历史兼容能力，不再作为独立一级页面维护。
- **发现**同时承载内容发现、学习课程和公开知识库订阅；它与“我的整理”的私人产物列表边界不同。

## 2. 当前信息架构

### 2.1 侧边栏

当前侧边栏由两个相关但不同的区域组成：

1. `整理`区域：点击标题进入工作台；展开后显示当前用户已经创建的整理配置。
2. `记忆`、`发现`区域：作为可见的独立菜单项，分别进入记忆和发现页面。

因此，当前可见菜单并不是旧 PRD 中简单的“工作台 → 我的整理 → 记忆 → 发现”四项平级菜单。`我的整理`仍然有独立路由，但主要从工作台卡片、整理详情和产物返回路径进入。

## 3. 用户流程

### 3.1 创建并执行整理

1. 用户进入工作台，选择“从模板创建”或“从空白创建”。
2. 配置名称、模板、整理指令、专家、执行周期和可选的目标服务。
3. 保存后形成一条用户自己的 `organize_config`。
4. 用户可以立即执行；配置为每日、每周或每月时，由调度器创建周期任务。
5. 每次执行形成一条 `organize_job`，执行完成后生成 `organize_output`。
6. 配置详情页按时间线展示任务，可查看产物、重试失败/降级任务或取消进行中的任务。

当前任务状态：

| 状态 | 含义 |
| --- | --- |
| `queued` | 已创建，等待执行 |
| `running` | 正在执行 |
| `repairing` | 正在修复或整理结果 |
| `completed` | 正常完成 |
| `fallback` | 生成了基础结果或降级结果 |
| `failed` | 执行失败 |
| `canceled` | 已取消 |

当前前端主要通过轮询刷新状态：工作台约 30 秒刷新一次，配置详情页在存在进行中任务时约 3 秒刷新一次。后端同时提供 `/api/v1/organize/jobs/:id/events` 事件接口，但当前页面没有以 `EventSource` 作为主要展示通道。

### 3.2 记忆输入和编辑

支持的记忆类型：

- `note`：笔记
- `record`：记录类记忆
- `audio`：录音
- `audio_card`：录音卡/工牌类记忆

输入方式：

- 直接创建记忆；
- 上传单个或多个文件；
- 音频转写后生成可编辑笔记；
- 记忆详情页编辑标题、正文、来源和时间；
- 查看附件、附件解析结果以及失败附件；
- 对失败附件执行重试。

附件状态：

`pending` → `processing` → `completed`，异常时进入 `failed`，不适合处理的附件可以为 `skipped`。

上传解析链路会尝试提取标题、摘要、标签、内容类型等元数据。它与“整理工作台任务”是两条不同的 AI 链路：前者服务于记忆/成果入库，后者服务于按整理配置生成产物。

### 3.3 产物归属服务

整理产物完成后有两种状态：

- 配置存在 `target_service_id`：执行时尝试自动归属服务；
- 没有目标服务或自动归属未完成：进入工作台“待归属”列表。

用户也可以在产物详情页手动选择服务空间。归属后，服务空间把该产物作为持续工作的背景资料。

### 3.4 发现内容、课程和公开知识库

发现页当前有两层内容：

1. **内容模式**
   - 顶部“精选”；
   - 下方按发现页签分页的图文/视频/音频等产物；
   - 已发布课程以课程卡片参与推荐；
   - 内容详情可以编辑、预览和维护发布状态。
2. **知识库模式**
   - 展示已发布的公开知识库；
   - 支持精选、推荐和“订阅/取消订阅”；
   - 使用公开知识库接口，不等同于当前用户自己的整理产物。

第一版发现栏目仍是固定配置，当前代码保留以下八类：

`招生增长`、`家长服务`、`活动策划`、`园所运营`、`团队运营/领导力`、`儿童营养与食育`、`空间设计 / 环创`、`教师成长 / 教研`。

这些栏目用于内容编辑和发现筛选，当前没有栏目管理页面，也不是动态标签管理。

### 3.5 课程发布和学习

课程是发现模块中的独立内容形态：

- 平台系统管理员在 Admin 的“系列课程”中创建课程元数据；
- 上传课程目录/文件，按文件生成课时；
- 课时复用 `organize_outputs` 作为内容来源，不另存一份正文；
- 课程可以发布、下线，并设置系统可见、指定共享空间可见或私有；
- 前台课程详情只先加载大纲，课时正文和媒体按需加载。

## 4. 当前数据模型

### 4.1 用户整理链路

| 表 | 作用 |
| --- | --- |
| `organize_memories` | 用户记忆主体 |
| `organize_memory_attachments` | 记忆附件及解析/转写状态 |
| `organize_outputs` | 整理产物和发现内容的主体 |
| `organize_output_memories` | 产物与输入记忆的关联 |
| `organize_sprout_reports` | 历史发芽报告兼容数据 |
| `organize_sprout_memories` | 发芽报告与记忆的关联 |

### 4.2 配置和执行链路

| 表 | 作用 |
| --- | --- |
| `organize_templates` | 平台/租户/个人范围的模板定义 |
| `organize_template_versions` | 模板版本快照 |
| `organize_configs` | 用户拥有的可复用整理配置 |
| `organize_jobs` | 单次执行、状态、进度、输入、模型和错误记录 |

`organize_jobs` 会记录 `template_key`、`template_version`、`prompt_hash`、`memory_ids` 和 `output_id`，因此可以追溯一次执行的模板和输入。

### 4.3 课程链路

| 表 | 作用 |
| --- | --- |
| `organize_courses` | 课程元数据、发布状态和可见范围 |
| `organize_course_lessons` | 课程课时顺序、标题、类型和关联产物 |
| `organize_course_shared_spaces` | 课程与共享空间的可见关系 |

课程课时通过 `output_id` 复用整理产物内容，上传、解析、编辑和前台学习使用同一份内容来源。

## 5. API 分组

所有用户整理接口位于 `/api/v1/organize`，当前路由在 `internal/router/router.go` 注册。

| API 分组 | 主要接口 |
| --- | --- |
| 概览/发现 | `GET /overview`、`GET /discover` |
| 模板/专家 | `GET /templates`、`GET /templates/scenes`、`GET /templates/:key`、`GET /experts` |
| 配置 | `GET/POST /configs`、`GET/PUT/DELETE /configs/:id`、`POST /configs/:id/run`、`GET /configs/:id/jobs` |
| 任务 | `GET/POST /jobs`、`GET /jobs/:id`、`GET /jobs/:id/events`、`POST /jobs/:id/retry`、`POST /jobs/:id/cancel` |
| 记忆 | `GET/POST /memories`、`POST /memories/upload`、`GET/PUT/DELETE /memories/:id`、附件重试 |
| 产物 | `GET/POST /outputs`、`POST /outputs/upload`、`GET/PUT/DELETE /outputs/:id`、`POST /outputs/:id/assign` |
| 发芽兼容 | `GET/POST /sprout-reports`、`POST /sprout-reports/from-memory`、`GET/PUT/DELETE /sprout-reports/:id` |
| 课程 | `GET /courses`、`GET /courses/:id`、课程封面、课时正文和课时媒体按需读取 |

权限边界：

- JWT 用户接口由当前登录用户和当前工作空间上下文决定数据范围；
- 普通用户的私有整理配置、记忆、任务和产物按本人隔离；已发布的发现内容、课程和公开知识库按各自的公开可见规则读取；
- API Key 目前只允许 full-access 组访问整理接口，没有单独的整理窄权限；
- 课程 Admin 接口位于 `/api/v1/system/admin/courses`，受 `SystemAdmin` 保护；
- 公开知识库订阅使用独立的 public knowledge-base API，不复用用户整理的私有 scope。

## 8. 后续维护规则

1. 页面、路由和接口有变化时，先更新本文件的“路由清单”和“API 分组”。
2. 新增整理能力时，同时补充“用户流程”“数据模型”和“实现状态对照”，不要只在 PRD 中追加目标描述。
3. 目标设计与实现事实必须分开：新需求写入 PRD，已经落地的行为写入本文件。
4. 如果旧路由继续保留兼容重定向，必须在路由清单中记录来源和目标，避免误删存量入口。
5. 发现内容、公开知识库和课程属于同一前台入口下的不同内容域；扩展时不要把它们与用户私人整理产物混为一个权限范围。
