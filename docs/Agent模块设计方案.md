# 睿乐大脑 Agent 模块设计方案

> v2.0 · 2026-10-10 · 配套原型：`docs/prototypes/Agent模块设计原型.html`（移动端 · 7 场景）
> 参考对象：阿福健康 App（门面形态）+ Famly/Frankie（主动型助手，2026-10-08 发布）+ illumine（2026-09-17 发布三 Agent）
>
> **v2.0 对齐记录（同日，随「服务空间下线」决策同步）**：① 分身**写回目标从「服务空间」迁到「待办」**——复盘写回 = 直接建待办 + 归档产出，全文不再以服务空间为落点；② 顾问第四卡「看台账」→「**问园区**」（原卡指向服务空间）；③ dock 第四项「服务」更名「**待办**」（它的落点本来就是待办聚合页）；④ 结果页引入「**先确认后执行**」——产出先给草稿，确认才落待办（Famly 产品原则 + 幼教合规）；⑤ 技能层加「**落地成本**」标记（改配置即上 / 待建），对齐研发排期；⑥ 首页那句话定性为「**早晨简报**」，每天 8:00 一次。
>
> **v1.1 简化记录**：① 首页文案四行 → **一行**（头像 + Hi + 角色）；② 分身"主动一句"从卡片降为**一句话**（信息不是入口）；③ **首页去掉输入条**，说话唯一入口 = 中央凸起键（点=对话，长按=录音）；④ 四卡角标只留真实数字；⑤ 技能层改轻列表；⑥ 结果页两个按钮 → 一个主按钮。

## 0. 一句话主张

**不做十个让用户挑的 agent，做一个按角色换身份的门面「分身」**——首屏只放 4 张能力卡，背后挂 10 项技能；回答靠记忆库，产出**先给草稿、确认后写回待办**，输入靠中央凸起采集键。

## 1. 背景与设计依据

### 1.1 问题

睿乐现有的 AI 能力散在三个模块：记忆（素材）、整理（加工）、服务空间（协作与待办，**已拍板下线，仅保留待办层**）。使用者要自己判断"这件事该去哪个模块做"，学习成本高；且模块之间没有统一的对话入口。

### 1.2 从参考对象学到的规律

| # | 参考对象的做法 | 对睿乐的启示 |
|---|-----------|-------------|
| 1 | 阿福：首页就是「阿福」一个拟人形象，用户不挑功能 | 门面收敛：一个分身，不是一个 agent 列表 |
| 2 | 阿福：2×2 能力卡，每张都高频、有专属输入、有服务闭环 | 首屏只放 4 张卡，卡名用用户语言 |
| 3 | 阿福：按住说话 + 相机常驻底部，多模态输入是一等公民 | 采集键升级为分身主输入：录完直接出活 |
| 4 | Famly：早晨简报 + 主动标记（逾期余额、失败付款） | 首页「早晨简报」每天 8:00 一次，异常项点名 |
| 5 | Famly：**助手在未获用户确认前，绝不执行动作** | 产出先给草稿，确认才落待办（写进验收标准） |
| 6 | 阿福：健康档案 + 就医闭环托底 | 记忆库 + **待办**就是我们的"档案 + 闭环" |

### 1.3 与通用助手的差异化判据（立项红线）

一个技能至少命中一条才立得住：

- **D1 私有数据**——吃机构自己的线索、沟通记录、出勤缴费、观察记录，通用助手拿不到；
- **D2 写回系统**——产出落进业务系统成为可执行物（待办 / 名单 / 归档），不是一段可复制的文本；
- **D3 持续在场**——定时或事件触发、跨周期累积，通用助手是一次性会话。

**"写得更专业、更漂亮"不算壁垒**——提示词就能抄走。

## 2. 信息架构

```
dock 四 tab（记忆 / 整理 / 发现 / 待办）不动，第四项「服务」更名「待办」
        │
        └─ 中央凸起键（现状=采集键）→ 升级为「分身」入口
                │
   ┌────────────┼────────────────┐
   门面层        首屏层            技能层
   拟人形象+招呼  按角色 2×2 四张卡   10 项技能全量可见
   +早晨简报      （见 §3）         （见 §5）
   └────────────┴────────────────┘
        输入条只在对话页出现；首页说话只走凸起键
```

- **落点（mobile 真机）**：dock 中央凸起键本就是采集键（录音/文字浮层），把它升级为分身入口改动最小；凸起键带红点表示"分身有话要说"。
- **分身页 = 冷启动默认落点**：打开 App 第一屏即门面。
- **待办 tab**：服务空间摘掉外壳后唯一保留的一层，也是分身的写回落点（见 §6.2）。

## 3. 三角色四卡

同一入口按登录角色换身份与卡片（角色由登录账号的岗位字段决定，界面上不出现切换控件）：

| 角色 | 身份名 | 早晨简报示例 | 首屏四卡 |
|------|--------|------------|----------|
| 招生顾问 | 招生搭子 | "今早 3 位家长要跟，其中 1 位昨天到访后没约下次。" | 录谈单 · 今日跟进 · 发家长 · 问园区 |
| 园长 | 经营搭子 | "昨日出勤 92%，有 2 位家长申请退费。" | 看日报 · 风险名单 · 投诉哨 · 问园区 |
| 班级老师 | 班级搭子 | "小二班今天还有 4 条观察没记录。" | 记观察 · 出报告 · 备沟通 · 教研夹 |

**选卡三筛**：高频（每周都在做）、有专属输入（录音/拍照本身就是入口）、有服务闭环（产出确认后落待办/归档）。**四张里必须留一张给纯问答**（"问园区"，对应阿福"AI 诊室"的位置）。

**⚠️ v2.0 改卡**：顾问第四卡从「看台账」换成「问园区」——「看台账」原指向服务空间（已下线）；空出的位置给本机构知识库问答（价格政策、课程话术怎么答），这是 D1 私有数据最直接的用法。

**卡名规范**：必须是用户语言（"录谈单"），禁止出现"XX Agent"这类工程师词汇。

## 4. 四个核心场景（对应原型场景 2–4）

### 4.1 早晨简报（原"主动一句"）

分身每天 8:00 开口说一句**只有它知道**的话（来自昨日经营数据 / 预警 / 待补记录）。这句决定了分身是"工具"还是"搭子"——阿福的拟人感来自形象，我们的拟人感来自**它主动知道的事**。Famly 验证过"早晨简报 + 主动标记"是这类助手的留存来源；底座（经营日报 / 到访复盘 / 风险名单）已经全有，只是合成一屏每天推一次。**它是内容不是入口**——不加跳转，能做的事在下面四张卡上。

### 4.2 对话带依据

每条回答尾部带「依据」回链（到访记录 9-28 · 通话记录 10-02 · 顾虑归纳 v1）。**这是与通用助手的可见差别**：通用助手给通用建议，分身给这家人的事。**回答只给一个动作按钮**（接着录谈单 / 看待办草稿），不要求用户自己再找功能。

### 4.3 采集执行

- 全屏录音态：计时 + 实时波形 + "上滑取消 · 松手完成"（对齐微信语音肌肉记忆）；
- **按下去之前就讲清楚结果**："录完的分身会做三件事：转写全文 → 提取关注点与卡点 → 整理成复盘等你确认"；
- 转写完成态给三步进度，把黑盒拆开，等待不焦虑；
- 一个键三种活：顾问=录谈单→复盘；老师=记观察→成长记录；园长=录会议→纪要。

### 4.4 结果与写回（先确认后执行）

- **结论先行**：复盘卡第一行就是结论，不是把转写念一遍；
- **三段固定结构**：关注点 / 卡在哪 / 下一步——与已上线的招生整理模板同口径；
- **⚠️ v2.0 核心改动：待办草稿 + 确认**。分身把"要做的事"拟成 2 条待办草稿（带勾选与优先级）先给用户看，底部唯一主按钮「确认并生成」；**不确认就不建**。三条理由：① Famly 产品原则"未获用户确认前绝不执行动作"；② 误操作与信任；③ 幼教合规要求助手不替人做承诺、不直接对家长发送。
- **同一信息只出现一次**：v1.1 的"已写回"回执与"看这 2 条待办"按钮是同一件事说两遍，v2.0 合并为"草稿 + 确认"，删掉回执；确认后直接落到待办清单。

## 5. 技能层（10 项）

首屏 4 张卡是入口，10 项技能是全部能力；技能层全量可见、按角色过滤、按业务分组。每项带两个标记：**壁垒**（讲给客户听的差异化）与**落地成本**（讲给研发排期用）。

| # | 技能 | 一句话 | 壁垒 | 落地成本 | 归属角色 |
|---|------|--------|------|----------|----------|
| 1 | 招生线索跟进 | 知道手里有谁的线索、今天该跟谁 | D1 D2 D3 | 待建 | 顾问（首屏） |
| 2 | 到访谈单复盘 | 录完直接出复盘，写回待办 | D1 D3 | **改配置即上** | 顾问（首屏） |
| 3 | 渠道转化归因 | 哪条渠道来的线索真签下来了 | D1 D3 | 待建 | 园长 |
| 4 | 续费与流失预警 | 出勤与缴费变化触发动作 | D1 D2 D3 | 待建 | 园长（首屏） |
| 5 | 投诉与情绪升级预警 | 家长的不满苗头早半天发现 | D1 D3 | 待建 | 园长 |
| 6 | 家庭沟通助手 | 基于孩子在园的真实记录说话 | D1 D2 | 待建 | 老师 / 顾问（首屏·老师） |
| 7 | 幼儿成长报告 | 老师不用自己回忆发生了什么 | D1 D2 | 待建 | 老师（首屏） |
| 8 | 园本教研资产 | 跨老师跨学期长成本园教研库 | D1 D3 | 待建 | 老师 |
| 9 | 经营数据日报 | 早上八点自己出，异常项点名 | D1 D2 D3 | **改配置即上** | 园长（首屏） |
| 10 | 在园健康与营养 | 过敏名单与晨检异常一起算 | D1 D2 | 待建 | 老师 / 后勤 |

**落地优先级**：改配置即上的 2 项（② 复盘、⑨ 日报）随 P0 上线；壁垒最厚的 ①④（三条全中）+ ⑤（价值在"早半天"的时间差）排 P1–P2。

## 6. 与现有模块的接线点

1. **整理模块**：技能 2、3、9 直接复用整理模板与周期任务机制（`visit_review` / `objection_ledger` / `win_loss_review` 已上线）。
   ⚠️ 已知约束：周期任务调度时刻写死（`organize_workbench.go:1175-1204`），且时间词解析出整段日历窗口含未来（`organize_selection.go:48-89`）——**技能配置的指令必须写「上一个周期」**，写"本周/今日"会命中为空。
2. **待办层（写回落点）**：`service_reminders`（待办，**服务空间下线后单独保留**）+ `organize_outputs`（复盘归档），不新建表。已摘掉：空间外壳 / 家庭档案（`service_facts`）/ 空间会话 / 模板 / 设置。
3. **记忆库**：分身回答的依据来源。
   ⚠️ 前置修复：租户未配 ASR 时音频正文退化成文件名且状态伪成功（`organize_memory_attachments.go:406-455`）——**不先修，"录谈单出复盘"在未配 ASR 的租户就是空转**。
4. **采集键**：mobile 端（`mobile/` Flutter）现有采集键交互改为分身入口；录音/拍照后即触发整理链路，产出回到对话，而不是只存记忆。
5. **专家口**：整理模板 `expert_ids` 目前全空——技能可绑专家带岗位视角（如"招生总监"复盘谈单）。
6. **岗位字段（前置依赖）**：在 `tenant_members` 加 `job_role`（顾问/园长/老师/教务），**不复用权限 `role`**——没有它，分身无法按角色换身份。

## 7. 分期落地建议

| 期 | 内容 | 量级 |
|----|------|------|
| P0 | 门面壳（分身 + 三角色四卡 + 技能层展示）+ 早晨简报；技能 2/9 接已上线的三个招生整理周期任务；写回目标切到待办层 | 改配置 + 前端 |
| P1 | 录谈单全链路（采集 → 整理 → 确认 → 落待办）；经营日报自动推送；ASR 退化修复；招生线索手工登记 + Excel 导入 | 接数据 |
| P2 | 续费与流失预警、投诉哨、成长报告、园本教研资产、渠道归因 | 新建 |

**验收**：按四条设计原则过一遍——一屏一件事 / 一屏一个主按钮 / 同一信息只出现一次 / 能一行说完不卡片。重点检查：首页除四卡与早晨简报外无任何多余卡片；数字不单独做 KPI 卡；**待办生成前必须有确认步**；写回结果必须可点进待办清单。

## 8. 明确不做

1. **不做 agent 列表页让用户挑**——列表是工程师视角；
2. **不做 C 端运营活动位**（阿福首页的打卡红包是获客打法，B 端工具首屏不放）；
3. **不推翻 dock 结构**——分身住进中央凸起键，四 tab 保持（第四项仅更名）；
4. **移动端零配置**——角色配置、技能开关、模板编辑全部只在电脑端；
5. **不做对儿童的安全 / 行为 / 发育判断**；不做儿童人脸与生物识别；儿童数据不用于训练第三方模型（幼教 AI 三条红线，写进验收标准）；
6. **不直接对家长发送任何内容**——发家长的草稿一律先经老师确认。
