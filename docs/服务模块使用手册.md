# 服务模块使用手册

> 适用版本：2026-10-14 当前代码版本  
> 适用范围：Web 主工程服务工作台、独立 Admin 工程服务模板管理  
> 使用对象：服务人员、服务管理员、实施人员、平台管理员

## 1. 模块说明

服务模块用于围绕一个持续服务对象集中开展工作。每个服务拥有独立的：

- 会话与历史记录；
- 家长、学员等服务主体信息；
- 重点记录和服务摘要；
- 待确认档案信息；
- 待办、负责人、评论和处理历史；
- 服务文件和整理资料；
- 成员、角色与分享范围。

服务中的聊天回复不等于档案已经更新。系统识别出需要沉淀的信息后，会生成“待确认”卡片；只有用户点击“确认更新”，数据才会写入服务档案。

### 1.1 主理人与成员 Agent

每个服务空间固定采用同一套运行结构：

- **一个主理人**：唯一承接用户会话，负责理解目标、拆解任务、控制过程并统一回复；
- **多个成员 Agent**：由主理人根据任务动态调用，不直接接管用户会话；
- **统一上下文**：主理人和成员 Agent 都在当前服务的权限、知识库和资料范围内工作；
- **统一交付**：成员 Agent 的结果先返回主理人，由主理人校验、取舍和汇总后再交付给用户。

Web 服务空间不提供“切换当前专家”的入口。Admin 模板中配置的是主理人可调用的成员 Agent，不是并列的服务负责人。

## 2. 入口与角色

### 2.1 主工程入口

登录主工程后进入：

```text
服务
```

本地开发默认路径：

```text
http://localhost:8081/platform/service
```

### 2.2 Admin 入口

具有管理员权限的用户进入独立 Admin 工程：

```text
资产配置 → 服务模板
```

本地开发默认路径：

```text
http://localhost:8082/admin/service/templates
```

### 2.3 服务成员角色

| 角色 | 查看服务 | 对话与处理工作 | 修改重点记录 | 管理成员和基本信息 |
| --- | --- | --- | --- | --- |
| 拥有者 | 是 | 是 | 是 | 是 |
| 管理员 | 是 | 是 | 是 | 是 |
| 可编辑 | 是 | 是 | 是 | 否 |
| 只看（只读） | 是 | 否 | 否 | 否 |

拥有者不可被普通成员移除或改为其他角色。

## 3. 管理员准备

### 3.1 创建服务模板

进入 Admin 的“服务模板”页面，点击“新建服务模板”，填写：

1. **模板名称**：面向业务人员的场景名称。
2. **服务场景**：家长与学员、园所日常运营或教研与备课。
3. **模板说明**：描述模板适合解决的问题。
4. **工作指令**：定义服务目标、重点记录、事实边界和工作方式。
5. **成员 Agent**：按需配置一个或多个可被主理人调用的 Agent；不配置时主理人仍可独立工作。
6. **知识库**：按需填写允许服务读取的知识库 ID。
7. **Skill**：按需填写服务需要调用的 Skill 标识。

学员档案类模板可使用以下工作指令：

```text
服务家长与学员，重点记录孩子姓名、年龄、班级、主班老师、课程和服务偏好。
用户提供新的档案信息时生成待确认提案，用户确认后才能写入服务档案。
涉及健康、安全、支付和身份的敏感内容，只记录完成服务所必需的信息。
```

保存后模板状态为“草稿”，检查配置无误后点击“发布”。只有已发布模板可以被模板应用接口使用。

### 3.2 当前版本的模板使用规则

普通“新建服务”弹窗只提交服务名称。服务激活创建时，后端会自动使用**当前租户最近发布的低风险模板**，并通过正式模板应用流程生成：

- 模板蓝图和工作指令；
- `facts` 来源的重点记录字段；
- 主理人、成员 Agent、知识库和 Skill 绑定；
- 初始档案与摘要。

需要注意：

- 模板按租户隔离，在其他租户发布的模板不会生效；
- 同一租户发布多条低风险模板时，最近发布的一条是 Web 默认模板；
- 发布模板不会自动修改已有服务；
- 在模板接通前创建的空白服务需要重新创建，或通过实施修复流程补建蓝图；
- 当前租户没有已发布模板时，后端仍保留旧版空白创建兼容行为。

实施或测试人员可以先查询当前可用模板：

```http
GET /api/v1/services/templates
```

再通过模板应用接口创建服务：

```http
POST /api/v1/services/templates/{template_key}/apply
Content-Type: application/json

{
  "name": "乐乐家庭服务",
  "template_key": "{template_key}",
  "idempotency_key": "service-test-20261014-001"
}
```

`idempotency_key` 必须保证同一次创建请求稳定且唯一，避免重复创建服务。

### 3.3 LLM 提案兜底

规则没有识别出档案字段时，后端可以使用 LLM 做灰度兜底。该能力通过服务进程环境变量控制：

```text
SERVICE_FACT_LLM_FALLBACK_TENANTS
```

这不是 Admin 页面配置项。短句档案更新不应完全依赖该兜底，常用字段应优先配置为明确的重点记录。

## 4. 创建服务

### 4.1 从服务列表创建

1. 进入“服务”。
2. 点击右上角“新建服务”。
3. 填写服务名称。
4. 点击“创建服务”。
5. 创建成功后系统自动进入该服务的首个会话。

建议使用能够识别对象和场景的名称，例如：

```text
乐乐家庭服务
秋季招生咨询
园所巡查服务
亲子活动教研
```

### 4.2 当前创建行为

当前普通创建会：

- 创建服务空间；
- 自动套用当前租户最近发布的低风险模板；
- 初始化模板蓝图、重点记录和摘要；
- 带入模板配置的专家、知识库和 Skill；
- 激活服务；
- 创建首个服务会话。

当前普通创建不会自动创建家长或学员主体。第一版允许模板将主体策略设为非必填，档案提案可直接写入服务级档案。

创建后应进入“更多 → 服务设置 → 重点记录”，检查模板字段是否完整带入。

需要注意：当前从设置页手工新增的重点记录主要用于档案结构和展示，聊天提案抽取尚未消费 `manual` 来源字段。需要通过聊天自动识别的字段，应由模板或工作指令生成，并以 `facts` 来源进入服务蓝图。

## 5. 服务列表

服务列表展示当前用户可访问的服务。

支持的操作包括：

- 按最近活动、创建时间或名称排序；
- 按服务名称和说明搜索；
- 点击服务卡片进入服务；
- 查看最近动态和新待办；
- 归档服务；
- 查看和恢复归档服务。

归档用于暂时停止日常展示，历史会话和服务数据仍然保留。删除属于永久性操作，应谨慎使用。

## 6. 服务工作台

进入服务后，工作台由以下区域组成：

| 区域 | 用途 |
| --- | --- |
| 中间会话区 | 与服务专家对话、处理工作、生成档案提案 |
| 历史会话 | 切换该服务下的历史会话 |
| 文件 | 查看、预览、下载、保存或归档服务文件 |
| 待办 | 处理待确认档案信息和服务待办 |
| 右侧信息栏 | 查看家长、学员、班级、主班老师和最近动态 |
| 更多菜单 | 修改信息、分享、查看概览和动态、进入设置、暂停、归档或删除 |

移动端或较窄窗口会隐藏右侧信息栏，主要工作仍在会话区和顶部操作入口完成。

## 7. 会话与档案确认

### 7.1 提供档案信息

在服务会话中输入明确事实，例如：

```text
孩子年龄是10岁
班级是4班
主班老师是李老师
家长比较关注周末上课时间
```

系统识别成功后，会在消息附近显示“识别到档案信息”确认卡。

### 7.2 确认卡内容

确认卡展示：

- 识别到的字段；
- 建议写入的值；
- 信息依据；
- 服务主体选择器，只有需要选择主体时显示；
- “忽略”和“确认更新”操作。

### 7.3 确认更新

点击“确认更新”后：

1. 提案状态变为“已确认”；
2. 信息写入服务事实；
3. 对应档案字段刷新；
4. 服务摘要按最新事实刷新；
5. 该提案从“要你确认”列表移除；
6. 确认结果保留在原会话消息附近。

### 7.4 忽略

点击“忽略”后：

- 信息不会写入服务档案；
- 提案状态变为“已忽略”；
- 该提案从“要你确认”列表移除；
- 历史会话仍保留处理结果。

### 7.5 重要判断标准

只有出现确认卡并完成“确认更新”，才能认为档案已经写入。

以下内容不能作为写入成功的依据：

- AI 回复“已经记录”；
- AI 在回复中复述了档案信息；
- 信息出现在聊天上下文中；
- 右侧信息栏暂时显示了模型生成内容。

如 AI 回复已经更新，但没有确认卡，应按“档案未写入”处理。

## 8. 待办

点击服务顶部“待办”打开侧边面板。待办分为两组：

### 8.1 要你确认

展示尚未处理的档案提案。可以直接：

- 确认更新；
- 忽略；
- 在要求主体时选择正确主体。

处理完成后，该项即时离开待确认列表，顶部数量同步减少。

### 8.2 要你去做

用于记录需要后续执行的工作。

新建待办时填写：

- 标题；
- 负责人；
- 时间说明。

待办支持：

- 按允许的状态流转到下一步；
- 修改负责人；
- 添加评论；
- 查看操作历史；
- 删除待办；
- 查看下级待办关系。

## 9. 文件

点击服务顶部“文件”打开文件面板。

文件面板支持：

- 查看文件名称、格式、版本和生命周期；
- 预览文件；
- 在允许下载时下载文件；
- 将临时文件保存为正式文件；
- 归档不再使用的文件。

文件数量显示在顶部“文件”入口旁。

## 10. 历史会话

点击服务标题区域的历史会话图标，可以：

- 查看该服务的全部会话；
- 按最近更新时间选择会话；
- 查看置顶状态；
- 返回历史对话及其确认结果。

每个会话必须归属于当前服务。切换服务时，不应看到其他服务的会话。

## 11. 服务概览

进入“更多 → 更多 → 服务概览”，可以查看：

- 当前进展；
- 分区服务摘要；
- 家长与学员信息；
- 最近动态；
- 重点记录及当前值。

点击“刷新摘要”可以根据当前事实、资料和待办重新生成服务摘要。

摘要是服务数据的聚合展示，不替代原始事实和操作记录。

## 12. 动态

进入“更多 → 更多 → 动态”，可以查看：

- 全部动态；
- 这一家的变化；
- 服务动作。

“这一家的变化”主要来自已确认的服务事实；“服务动作”主要来自待办及其状态。

动态按日期分组展示，用于回顾服务过程，不作为完整审计日志替代品。

## 13. 服务设置

进入“更多 → 更多 → 服务设置”。

### 13.1 基本信息

拥有者和管理员可以修改：

- 服务名称；
- 服务说明。

家长、学员、班级和主班老师信息在当前页面只读。

### 13.2 重点记录

拥有者、管理员和可编辑成员可以：

- 从推荐字段中添加重点记录；
- 修改字段名称；
- 删除不再需要的字段；
- 保存档案结构。

客户服务默认推荐：

- 当前阶段；
- 核心诉求；
- 沟通记录；
- 风险信号；
- 下一步动作。

如需通过聊天自动识别年龄、班级等信息，应优先在当前租户的服务模板工作指令中声明这些字段，并发布为 Web 默认模板。

修改重点记录只改变后续记录结构，不应静默改写已有事实。

当前设置页手工新增的字段来源为 `manual`，聊天提案抽取暂时不会读取这类字段。手工新增字段可用于档案结构展示，但不能作为确认卡必然出现的依据。

### 13.3 资料

资料页展示已带入当前服务的整理结果。

可编辑成员可以移除不再需要的资料。移除后，该资料不再作为当前服务的背景上下文使用。

### 13.4 成员

拥有者和管理员可以：

- 从当前工作空间成员中选择人员；
- 添加为管理员、可编辑或只看角色；
- 调整非拥有者成员角色；
- 将非拥有者成员移出服务。

## 14. 分享和服务状态

### 14.1 分享范围

服务支持：

- 仅自己可见；
- 当前空间成员可见。

涉及敏感客户信息时，应优先保持“仅自己可见”，再通过成员管理添加明确的协作人员。

### 14.2 暂停服务

暂停用于临时停止服务运行。服务数据和历史记录仍然保留，可以再次恢复。

### 14.3 归档服务

归档后服务从日常服务列表移入“归档服务”，以后可以恢复。

### 14.4 删除服务

删除属于永久性操作，不等同于归档。执行前应确认不再需要服务会话、档案、待办和文件。

## 15. 推荐使用流程

建议按照以下顺序使用服务模块：

1. 管理员在业务服务所在租户准备并发布服务模板。
2. 通过普通“新建服务”弹窗创建正式服务，并检查重点记录是否自动带入。
3. 进入服务设置，检查重点记录；手工补充项当前只用于档案结构和展示。
4. 添加需要协作的成员并设置角色。
5. 带入已有整理资料。
6. 在会话中推进具体工作。
7. 处理“要你确认”中的档案提案。
8. 为后续动作创建待办并分配负责人。
9. 在服务概览检查档案和摘要。
10. 在动态中回顾事实变化和服务动作。
11. 服务结束后归档，避免直接删除。

## 16. 验证流程

使用以下流程验证服务模块是否正常：

1. 在业务租户的 Admin 中创建并发布测试模板，工作指令中写明“重点记录年龄、班级”。
2. 通过普通“新建服务”弹窗创建测试服务，并进入首个会话。
3. 输入“孩子年龄是10岁”。
4. 确认消息附近出现“年龄 = 10岁”的待确认卡。
5. 刷新页面，确认卡仍然存在，档案尚未写入。
6. 点击“确认更新”。
7. 进入服务概览，确认年龄显示为10岁。
8. 输入“班级是4班”。
9. 点击“忽略”，确认班级没有写入档案。
10. 再次输入“班级是4班”并确认。
11. 刷新页面，确认已处理结果仍归在原会话附近。
12. 创建一条待办，指定负责人和时间。
13. 修改待办状态并添加评论。
14. 在动态页面确认档案变化和待办动作均可查看。
15. 切换历史会话，确认会话不会跨服务串联。

## 17. 常见问题

### 17.1 输入档案信息后没有确认卡

检查：

1. 当前会话是否从服务工作台进入；
2. 会话是否绑定当前服务；
3. 服务蓝图是否包含对应的 `facts` 来源字段，仅在设置页看到同名字段并不足以证明可以抽取；
4. 用户输入是否明确包含字段和值；
5. 待办面板的“要你确认”中是否已经存在提案；
6. 后端是否成功创建 `service_fact_proposals`。

当前规则优先按字段名称和别名匹配。字段不存在时，“班级是4班”等短句可能无法生成提案。

设置页手工新增的 `manual` 字段当前不会进入聊天提案抽取；应检查服务蓝图中的对应字段是否为 `facts` 来源。

### 17.2 AI 说已经更新，但档案没有变化

AI 回复文字和档案写入是两条独立链路。没有出现确认卡并点击“确认更新”，就没有完成档案写入。

### 17.3 Admin 已发布模板，新建服务仍没有字段

依次检查：

1. Admin 当前选择的租户是否与业务服务所在租户一致；
2. 模板状态是否为“已发布”，风险级别是否为 `low`；
3. 多条模板同时发布时，目标模板是否是最近发布的一条；
4. 服务是否在模板发布后通过普通弹窗重新创建；
5. 服务详情的 `template_key`、蓝图和档案 schema 是否已经生成。

创建后在服务设置中手工增加字段只能补充档案结构，当前不能替代模板中的 `facts` 来源字段。

### 17.4 无法确认档案更新

检查：

- 当前用户是否至少具有可编辑角色；
- 提案是否要求选择服务主体；
- 服务是否处于可操作状态；
- 请求是否返回权限或主体缺失错误。

### 17.5 看不到成员管理操作

只有服务拥有者和管理员可以管理成员。可编辑成员只能处理业务内容，只看成员只能查看。

### 17.6 刷新后确认结果消失

正常情况下，提案通过 `assistant_message_id` 归回原消息，刷新后不应消失或重复。出现问题时应检查提案是否保存了会话 ID 和 assistant message ID。

## 18. 当前版本已知边界

- 普通新建服务会使用当前租户最近发布的低风险模板；没有已发布模板时仍会回退旧版空白创建；
- Admin 页面暂未提供档案字段和别名的独立可视化编辑器，字段主要根据工作指令生成；
- 服务设置中手工新增的 `manual` 重点记录暂未接入聊天提案抽取；
- LLM 档案提案兜底默认关闭，并且不是 Admin 配置项；
- 动态页面当前聚合服务事实和待办，不是完整审计日志；
- 服务级后端权限仍在持续收紧，敏感服务应同时使用私有可见范围和明确成员列表；
- Flutter 移动端完整能力需要按移动端计划单独验收。

## 19. 使用验收标准

服务模块可投入使用至少应满足：

- 服务可以创建、进入、暂停、归档和恢复；
- 每个会话严格归属于一个服务；
- 明确档案信息能够生成待确认卡；
- 用户确认前不写入服务事实；
- 确认后档案、摘要、动态和待确认数量同步更新；
- 忽略后不写入档案；
- 刷新后提案及处理状态不丢失、不重复；
- 待办支持负责人、状态、评论和历史；
- 文件可以预览并按权限下载；
- 拥有者、管理员、可编辑和只看（只读）角色行为符合权限范围；
- 不同服务之间的数据、会话和成员不会相互串联。
