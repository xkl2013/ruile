### 1.6 动态 · 时间线（v1.15，新能力）

- 整页 `/platform/service/:serviceId/activity` + 服务概览底部嵌 3 条 +「查看全部」。
- 筛选：全部 / 只看主体变化 / 只看空间动作 / 按主体。
- **主体变化行** = 主体名 · 字段 · 旧值 → 新值 · 依据（可回链会话/整理记录）· 操作者。
- **空间动作行** = 主体增改、资料带入/撤销、产物更新、成员变更、服务暂停归档、**待办终态**（v1.19：**只记已完成/已取消**，过程翻转不记）。
- **不建新表**，三个数据源：
  1. 主体变化 = `service_facts`（append-only），读接口已有 `GET /:service_id/facts`（`router.go:1610`）；
  2. 空间动作 = `audit_logs` 的 `service.*` 事件；
  3. 待办终态 = `service_reminder_history`（`service_id` 是一等索引列，`types/service_reminder_collaboration.go:68`），不走 audit。

## 2. 待办状态：全自动零配置（v1.8）

1. 默认 4 态（待处理/进行中/已完成/已取消），建服务时自动生成；界面无「配置状态」入口。
2. 工作指令点名的阶段由 AI 补充（与重点记录派生同链路，带「指令」角标）。
3. 流转说明收进待办浮层底部一行只读文字；**不设自定义入口**（注意：statuses CRUD 接口是齐的 `router.go:1615-1620`，不做入口是产品取舍）。
4. 建议后端把迁移 000113 的 9 态默认机收窄为 4 个用户态，`is_system` 机器态不下发前端。

## 7. 明确不做（避免范围蔓延）

1. **不动表结构**——蓝图三表保留，只撤界面出口。
2. **不删能力**：档案 / 摘要 / 主体 / 状态机 / 协作全保留，只降层级；唯一删掉的必经流程是蓝图确认弹窗。
3. **不做「资料」输入框 chip**（已拍板 2026-10-05）。
4. **不做待办状态自定义入口**（接口虽有，属产品取舍）。
5. **不做运行记录 / 高级分区**（运行记录缺列表接口，为一个低频只读页新增接口不划算）。
6. **不做服务级 ACL 完整实现**（B7 单独立项）。
7. **不动整理模块（Organize）的产出与带入协议**。
8. 存量服务不重写 `space_type`；存量 key 一律保留。
