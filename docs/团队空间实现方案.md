# 团队空间实现方案

## 1. 目标

将现有“共享空间”收敛为企业内部的“团队空间”，解决企业内部特定成员查看指定数据的问题：

- 团队空间只服务于企业空间内部的成员分组。
- 成员权限与知识库发布关系分开管理。
- 一个知识库可以发布到多个团队空间，不复制数据、不迁移索引。
- 共享智能体可以复用，但智能体配置不能替代知识库授权。

产品交互参考 WorkBuddy 的个人空间、团队空间和可见范围分离思路；不复制其未公开的内部实现：
<https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Library>

## 2. 当前项目的落地方式

本期复用现有表和接口，避免线上知识库迁移：

| 产品概念 | 当前实现 |
| --- | --- |
| 团队空间 | `organizations` 中 `sharing_scope=tenant_internal` 的记录 |
| 团队空间归属 | `organizations.owner_tenant_id` |
| 成员 | `organization_tenant_members.representative_user_id` 对应的具体账号 |
| 成员角色 | `admin`、`editor`、`viewer` |
| 知识库发布 | `kb_shares`，一条记录表示向一个团队空间显式发布 |
| 智能体共享 | `agent_shares`，只授予智能体使用入口 |
| 兼容接口 | 继续保留 `/organizations`、`/shared-knowledge-bases` 等旧路径，前端展示改为“团队空间” |

## 3. 权限规则

### 3.1 团队空间成员边界

- 新建团队空间时固定 `sharing_scope=tenant_internal`。
- 新增成员时，目标成员的企业空间必须等于 `owner_tenant_id`。
- 个人空间不能创建或加入团队空间。
- `tenant_internal` 团队空间的读写路径要求当前激活空间等于 `owner_tenant_id`；同一账号切到个人空间或其他企业空间时不能继续使用该团队空间权限。
- 历史 `legacy_cross_space` 数据保留原数据，不自动改写为团队空间。

### 3.2 知识库发布边界

- 知识库必须通过 `kb_shares` 显式发布后，团队空间成员才能查看。
- 取消发布立即撤销列表、详情、文件、搜索、下载和编辑入口。
- 知识库仍归原企业空间所有，发布不改变 `knowledge_bases.tenant_id`。
- 订阅只作为快捷入口，不能绕过知识库访问校验。

### 3.3 智能体边界

- 共享智能体仍可被团队空间成员使用。
- 智能体的 `KBSelectionMode` 只表示智能体希望使用的范围。
- 实际知识库范围为：

```text
共享智能体配置范围 ∩ 当前账号已拥有的知识库访问权限
```

- 共享智能体不能单独让成员打开知识库详情、文件、搜索、下载或编辑接口。
- 团队空间知识库列表只统计显式发布的知识库，不再把智能体绑定的知识库作为隐式共享知识库。

## 4. 本期代码改动

- 增加团队空间成员的所属企业空间校验和对应的 403 错误。
- API 返回 `sharing_scope`，前端可区分历史空间和企业内部团队空间。
- 会话 QA、Agent QA、@ 提及、知识库列表、文件批量读取和文件搜索统一应用成员可访问范围。
- 移除知识库访问中“通过共享智能体自动授权”的兜底路径。
- 团队空间知识库列表、资源数量只使用显式 `kb_shares`。
- 个人版隐藏团队空间、成员管理等企业协作入口；直接访问团队空间路由会被引导回可访问页面或进入无权限页。
- 企业版成员管理和团队空间入口位于主站用户侧「设置 → 团队 → 成员管理、空间管理」；个人版不渲染「团队」分组，Admin 不再提供独立入口。
- 成员管理展示当前企业空间的全部成员，复用既有成员、邀请、角色、审计和员工分身接口；Admin 旧成员管理地址仅保留兼容跳转。
- 知识库和智能体发布弹窗只列出 `tenant_internal` 团队空间，历史 `legacy_cross_space` 不作为新的发布目标。
- 管理后台和主站中文、英文、韩文、俄文入口改用 Team Space/团队空间表述。
- 未新增知识库、文档、分块或向量索引迁移。

## 5. 对线上知识库的影响

### 不会发生的变化

- 不复制知识库数据。
- 不修改知识库所属企业空间。
- 不修改文档、分块、向量或对象存储路径。
- 不触发重新解析、重新向量化或索引重建。
- 既有显式知识库发布关系继续有效。

### 需要重点验证的变化

历史上如果用户仅通过“共享智能体绑定知识库”使用知识库，而没有对应的 `kb_shares` 显式发布，升级后该知识库会从成员的知识库列表和 Agent 检索范围中消失。这是本方案有意收紧权限的结果，不是数据丢失。

线上升级前应先生成审计报表：

1. 共享智能体及其绑定知识库。
2. 使用该智能体的团队空间成员。
3. 绑定知识库是否存在对应团队空间的 `kb_shares`。
4. 缺少显式发布关系的知识库和影响人数。

后续线上升级脚本只负责审计、人工确认后的发布关系补齐、校验和回滚记录，不自动复制或迁移知识库内容。

## 6. 验收标准

### P0：必须通过

- 个人版账号看不到团队空间入口，直接调用创建或加入接口返回 403。
- 企业版账号在主站「设置」中看到一级「团队」和二级「空间管理」，点击后进入团队空间管理页。
- 企业版账号在主站「设置 → 团队」中看到「成员管理」，页面展示当前企业空间的全部成员，并沿用既有成员管理权限。
- 旧 `/admin/workspaces/current/members` 和 `/admin/workspaces/current/audit-log` 地址跳转到主站「设置 → 团队 → 成员管理」。
- 个人版账号在设置中看不到「团队」分组，直接打开主站或 Admin 团队空间路由时，不进入团队空间管理页面。
- 同一账号同时拥有个人空间和企业空间时，切到个人空间不能列出、打开、删除或使用企业空间下的团队空间资源。
- 企业版账号可以创建团队空间，创建者自动成为管理员。
- 企业内部团队空间只能添加 `owner_tenant_id` 所属企业空间的有效账号；跨企业账号、个人账号均返回 403。
- 成员可以加入多个团队空间；非成员无法读取团队空间成员、知识库和智能体列表。
- 知识库发布到团队空间后，只有该团队空间成员能看到；未发布到该团队空间的知识库不可见。
- 同一个知识库发布到两个团队空间时，两个空间的成员都可以访问；撤销其中一个发布关系不影响另一个空间。
- 取消发布后，知识库列表、详情、文档列表、全文搜索、下载、编辑和问答检索均不能继续访问。
- 仅共享智能体、不发布知识库时，成员可以看到并使用智能体，但不能因此打开该知识库详情、文件或下载接口。
- 企业内成员可以看到并使用发布到本企业团队空间的同租户共享智能体。
- 共享智能体问答只检索“智能体配置范围与成员可访问范围”的交集；未发布知识库不能出现在检索目标中。
- 订阅知识库不能绕过上述访问控制。

### P1：应通过

- 团队空间管理员可以添加、移除成员并调整成员角色。
- `viewer` 不能编辑知识库，`editor` 可以按发布权限编辑，管理员可以管理团队空间和发布关系。
- 旧 `/organizations` 及相关共享接口仍可被旧客户端调用；响应增加 `sharing_scope` 时不破坏旧字段。
- 历史 `legacy_cross_space` 数据可继续读取，且不会被本期自动迁移。
- 知识库和智能体发布弹窗只展示 `tenant_internal` 团队空间，不再展示历史跨空间记录作为新发布目标。
- 页面刷新、重新登录和切换团队空间后，列表与权限结果一致。

## 7. 建议验收数据

准备一个企业空间和四个账号：

- `owner`：企业空间管理员。
- `sales_user`：仅加入销售团队空间。
- `hr_user`：仅加入人事团队空间。
- `outsider`：不加入任何团队空间。

准备两个知识库：

- `sales-kb`：只发布到销售团队空间。
- `private-kb`：不发布，只绑定到共享智能体。

准备一个共享智能体：

- `sales-agent`：绑定 `sales-kb` 和 `private-kb`，共享到销售团队空间。

预期结果：

- `sales_user` 可以使用 `sales-agent`，但只能检索 `sales-kb`。
- `hr_user` 和 `outsider` 看不到 `sales-kb`、`private-kb` 和 `sales-agent`。
- `sales_user` 不能通过 `agent_id`、知识库 ID、文档 ID 或下载 URL 访问 `private-kb`。
- 将 `private-kb` 显式发布到销售团队空间后，`sales_user` 才能在允许的权限范围内访问它。
